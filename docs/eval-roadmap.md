# 以 RSI 为主的评测路线（Evaluation Roadmap）

> 这份文档回答一个问题：**「你的数字凭什么可信，而且下一次为什么还会更好？」**
> 答案不是"我很努力"，而是**一整套递归自我改进（RSI）的评测基建**：每回合只动一个变量、判据先写死、失败也入库。

## 一、五个零件，各自对应仓库里的什么

| 零件 | 在这里是什么 | 具体产物 |
|---|---|---|
| 任务执行器 | `eval/run-r1.ts`（dev / 幻影集）、`eval/run-audit.ts`（real，冻结账本） | `runs/exp-XXX/r1.result.json` + `trace.jsonl`（每条漏报带命题 id、在场记录、最早知情场景） |
| 改进提议器 | 读 trace 提假设，只做最小改动 | 例：回合 30 发现 10 条漏报中 7 条同因「泄漏台词自己新建了命题」→ 只改 `merge.ts` 一个函数 |
| 评测器 | `run-r1` + `run-audit` + `regression`（K 次 + Wilson） | 结果、诊断、成本三件套；`--reuse` / `--remerge` 两种冻结模式 |
| 搜索控制器 | 开关 + 默认值 + 预算 | 四个候选（`R1_MERGE_EXACT` / `OVERLAP` / `NO_SELF_ESTABLISH` / `SHOULD_ALLOW`）只有 `OVERLAP` 翻默认；留出集解封计数 |
| 版本与实验记录库 | `evalsets/index.json`（`testset@ver#hash`）、`scorer.ts`/`version.ts`（scorer/ctx 戳）、`experiments/exp-XXX.json` | 48 条记录：父版本、改动、结果、`candidate · accepted · rejected` |

## 二、每回合的预注册（先写死，再动手）

1. **范围**：这一轮只动哪一层（例：只改归并，不碰抽取、不碰标注集）。
2. **目标**：修掉什么问题、达到什么效果（例：同义改写召回 1/8 → 5/8）。
3. **评测器**：什么样算通过（例：dev P/R/cost 不退、real 不 +2、幻影集召回 ≥5/8）。
4. **历史路径包**：以前试过什么、为什么被否（`docs/rsi-protocol.md` 的回合记录）。

## 三、数字纪律（代码强制的部分）

- **四类版本戳**：`testset` / `scorer` / `contextProtocol` / `ledger` 指纹，任一不一致 ⇒ 两个数字不可比，只各自当新基线。
- **冻结上游**：R1 层改动用 `--reuse`（冻结抽取）；归并层改动只能 `--remerge`（冻结抽取、只重跑归并）。两种模式**不可混比**。
- **留出集封存**：解封一次记一次，已用 3 次 —— 不再用它选版本。
- **统计门槛**：比例指标一律带 95% Wilson；配对比较用 McNemar，**不一致对 < 6 不下结论**。
- **失效绿灯防线**：判定服务区域封锁（451）时管线会静默降级 —— 现在有 `judgeWatch`，失败即中止且不落缓存。

## 四、三套互不可比的指标（当前基线）

| 指标 | 值 | 用途 |
|---|---|---|
| dev（注入 10 条） | P 50.0% / R 30.0% / cost 24 | **只用来防退步**（区间宽 50–60pp） |
| real（两本专业剧本，零标注） | 7/269 = **2.6%**、7/165 = **4.2%** | 最有分辨力；**+2 条即回退** |
| 跨剧本 holdout | P 28.6% / R 20.0% | 已解封 3 次，封存不再用于选版本 |
| 机制探针（幻影集） | phantom **1/8** · anchored **7/8** | 指出主瓶颈在"说法匹配 + 归并粒度" |
| 端到端（命题级） | 25.67/48（K=3 均值），95% Wilson 39.6–66.8% | 只看趋势，单次无裁决权 |

## 五、下一轮具体计划（可执行）

1. **扩幻影集 8 对 → 30+ 对**（一条 ≈3pp 分辨率），重建基线；
2. **加语义检索通道**（嵌入召回 → 判定器确认），跑 A/B：phantom 召回 / dev 不退 / real 不 +2；
3. 若通过则翻默认；否则把"未通过 + 原因"写进实验库，进入下一假设；
4. 误报治理只在 `should_allow` 桶上再试一次（判定层批量问 + 缓存），仍然三条判据不过就收手。

## 六、为什么这套流程本身就是产品能力

因为产品卖的是**"这个角色此刻该不该知道"**这种判断 —— 它天生需要**可复现、可审计、可回退**。
一个只能演示、不能复核的规则系统，客户第二天就会关掉它。
所以评测基建不是"提交前的作业"，而是**产品的一部分**：48 条回合记录、5 套测试集、3 次解封计数，都在仓库里公开可查。
