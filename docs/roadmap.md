### 1.7 为什么缺的是「索引层」，不是「更强的判官」

**现状（别把它想成 LLM wiki）**：落盘的结构只有三条边 —— `命题 → 说法（aliases，逐字原文 + 首见场景）`、`命题 → 施事/在场者`、
`人物 → 命题 → 场景（knowledge）`。设计里给命题留了 `relation / agent / patient / object / type` 槽位，**实测是空的**
（`.ledger` 里 E-001 之类全为空串，归并喂给判官的候选 `type` 也是空串）。所以**没有跨命题的关系索引，也没有实体图**。
召回层每次现算字符 bigram 相似度，**不落盘** —— 它没有"索引"可查，只有"别名表里已经有的字面"。

**病根是循环依赖**：说法只有在被**归并成功**之后才成为某条命题的别名。于是
`换说法 → 挂不上 → 不成别名 → 下次更挂不上`。别名表**永远学不到它漏掉的东西**，"越用越厚"只在复述原话时成立。

**要修的层**（按代价排序）：

| 做法 | 索引从哪来 | 代价 | 备注 |
|---|---|---|---|
| A. 抽取时把实体/事件要素真正落盘 | 抽取契约加字段：`实体 · 谓词 · 客体 · 时间` | 中；提示词改动（历史上改主抽取 prompt 失败过 3 次，必须独立成第二遍或后处理） | 要素用于**召回**，不用于判定 |
| B. 离线「同一件事」聚类审查 | 只看命题对，不看台词，成对判定 | 高（N² 需剪枝）；但可人工复核 + 写进 `waive` | 能治历史欠账，一次性 |
| C. 对 canonical+别名建向量索引 | 向量是别名的函数 | 中；provider 可复现性问题 | **仍有种子问题**：种子只能是已有别名，治不了从未挂上的说法 |

**职责划分（本轮定下的口径）**：召回层用**要素/关系**（符号、宽召回、便宜）；判定层用**说法/字面**（窄确认、准）。
依据是设计文档 §6.3.1 的两组对照：候选换成结构化三元组 **±0pp**、补上典型表述 **+43.8pp** —— JEV 靠字面线索工作。
所以就算索引建好了，喂给 JEV 的仍要是"说法"，而**要素的用途是把候选捞进来**。

**JEV 不会被索引取代的三件事**：① 建索引时的抽取判断（这段文本里有没有一个事实、施事/受事是谁）；
② 符号证据不足时的归并仲裁；③ 审计时的语用判断（否定/假设/转述，以及目击、当事人、公开信息等合法渠道）。
索引做得好，② 会大幅收缩（回落到查表），① 和 ③ 不会消失。

## 阶段 2 · 误报治理（`should_allow` 桶）

- 已失败过三次（词表 / 判定层 / 问句），结论是**"在问细节"与"在暗示自己知道"词法不可分**。
- 下一步只走一条：**判定层只对"已报出的候选"问一次「当事人 / 目击 / 被专门告知 / 公开信息」**，
  并且必须解决它上一轮的两个问题：单次审计多 470s（→ 只对候选批量问，缓存结果）、会放过真泄漏（→ 仅在 real 上验证不 +2 且幻影集召回不掉）。
- 验收：real 7 → ≤5 条，dev 不退，幻影集召回不掉。

## 阶段 4 · 场景扩展（谨慎）

- 多媒介：漫剧（分镜脚本）、互动叙事（分支状态）——本质都是"知识状态 + 时间序"，但要先证明账本能覆盖分支合并。
- 长剧：80 集量级的建账耗时与增量并入（当前 23 场 14s；需实测 200 场）。
- 团队协作：账本随 git 走，冲突合并策略需要设计（当前是最后写入者胜）。

## 不做的事（明确排除，避免走回头路）

- 不往主抽取 prompt 里堆字段（试过三次，都变差）；
- 不用「更多规则」修召回（规则数量不是瓶颈，说法匹配才是）；
- 不跨抽取比较 `real`（重抽噪声 ≈±1–2 条，与红线同量级）。
