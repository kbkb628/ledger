# 后续改进路线（Roadmap）

> 排序原则：**先修"让数字可信"的东西，再修"让数字变好"的东西**；每项都写明验收标准，避免"看起来很忙"。

## 阶段 0 · 已经把地基打完（现状）

- MCP 六工具跑通：`ledger_ingest` / `ledger_record` / `ledger_check` / `ledger_audit` / `ledger_page` / `ledger_waive`
- 真客户端实测：DSH 内真实拦截、Claude Code `✓ Connected`、空目录 `npx -y ./tgz` 可装可跑
- 评测基建：四类版本戳（testset / scorer / context / ledger）、冻结基线、48 条回合记录、5 套剧本级测试集
- 已知短板（写在明处）：**换了说法就抓不到** —— 幻影集 v3（60 对，配对设计）基线 **phantom 17/60 · anchored 49/60**

## 阶段 1 · 解「说法匹配」这一层（最高优先级）

| # | 动作 | 状态 | 读数 |
|---|---|---|---|
| 1.1 | 幻影集 8 → 30 → **60 对** | ✅ 回合 50 / 52 | `phantom 17/60 = 28.3%` vs `anchored 49/60 = 81.7%`（差 53.4pp）；v1/v2 读数均作废 |
| 1.2 | 候选召回第二通道（罕见词 IDF） | ⚠️ 回合 51 / 53 · `candidate` | 60 对上 `phantom 23/60`（+7/-2 条，误报 5→3），但 McNemar p=0.18（phantom 子组 p=0.07）→ **仍未达显著**；归并花费 +121% → 默认关 |
| 1.3 | **改度量方式：拆成两段** | ⏭ 下一步（先做） | ①**候选召回率**：确定性、不需要判官 —— 「确立命题 id 是否进了这条 draft 的候选表」，60 对即可闭合；②判官挂载率：只在「候选已召回」的子集上算，样本小但更纯 |
| 1.4 | 语义检索（embedding）作第二通道 | 待 1.3 | 先定可复现 provider，并计入三戳 |
| 1.5 | 成本治理（1.2 的 +121%） | 待 1.3 | 候选去重 / 只在 ID 分不足时补 / 与判官批量化合并 |

> 判据固定：**dev P/R/cost 不退 · real 不 +2 · 幻影集召回提升 · McNemar 不一致对 ≥6 且 p<0.05**。
> 两次翻倍仪器（8→30→60）后效应稳定在「+5~7 条、p≈0.07~0.18」：按此效应量反算 80% 功效需 **150 对以上**。
> 所以 1.3 的结论是：**问题不在样本量，在度量方式** —— 先把确定性的那一半量准。

## 阶段 2 · 误报治理（`should_allow` 桶）

- 已失败过三次（词表 / 判定层 / 问句），结论是**"在问细节"与"在暗示自己知道"词法不可分**。
- 下一步只走一条：**判定层只对"已报出的候选"问一次「当事人 / 目击 / 被专门告知 / 公开信息」**，
  并且必须解决它上一轮的两个问题：单次审计多 470s（→ 只对候选批量问，缓存结果）、会放过真泄漏（→ 仅在 real 上验证不 +2 且幻影集召回不掉）。
- 验收：real 7 → ≤5 条，dev 不退，幻影集召回不掉。

## 阶段 4 · 场景扩展（谨慎）

- 多媒介：漫剧（分镜脚本）、互动叙事（分支状态）——本质都是"知识状态 + 时间序"，但要先证明账本能覆盖分支合并。
- 长剧：80 集量级的建账耗时与增量并入（当前 23 场 14s；需实测 200 场）。
- 团队协作：账本随 git 走，冲突合并策略需要设计（当前是最后写入者胜）。

## 不做的事（明确排除，避免走回头路）

- 不往主抽取 prompt 里堆字段（试过三次，都变差）；
- 不用「更多规则」修召回（规则数量不是瓶颈，说法匹配才是）；
- 不跨抽取比较 `real`（重抽噪声 ≈±1–2 条，与红线同量级）。
