# 调研报告：「知情一致性」值不值得单独做一个产品

> 调研时间窗：2026-10 · 结论时间：2026-10-18
> 这是**先调研、后立项**的记录：先回答「问题是否真实 / 现有方案是否覆盖 / 独立产品是否必要」，再决定做什么形态。
> 每条证据都标注「能看到哪一层」（全文 / 摘要级），避免把标题当结论。

---

## 0. 摘要

- **结论**：应该做，但**不该做成"更强的生成模型"**，应当做成**独立的、可查询的知识状态账本 + 一个挂载点**。
- 三重外部证据：① 行业公开把"一致性"称为 **AI 短剧商业化的瓶颈**；② 学界把 long-form 的记忆/一致性列为开放问题；③ 从业者亲口描述"断裂 → 观众不买单"的链条。
- 一处关键空白：上述方案解决的几乎都是 **画面/主体一致性**（脸、道具、场景），**没有一层在管"角色此刻该不该知道这件事"**。
- 一条自有量化：两本**零标注**专业剧本上，"无源使用"报出率 **2.6% / 4.2%** —— 说明这一层确实存在且**可度量**。
- 最大局限：**未做创作者访谈**，一手需求证据缺失（见 §5）。

---

## 1. 调研问题与方法

### 1.1 三个问题

| 编号 | 问题 | 为什么要问 |
|---|---|---|
| Q1 | 「一致性」是否被行业/学界**公开认定为瓶颈**？ | 若只是我们自己的体感，不值得做产品 |
| Q2 | 现有方案覆盖到哪一层？**知情层是否空白**？ | 决定是"改进现有工具"还是"新做一层" |
| Q3 | 值不值得做成**独立产品**，而不是一个提示词 / skill？ | 决定形态与投入 |

### 1.2 方法（四路交叉验证）

1. **公开报道与厂商访谈原文检索**（财经 / 科技媒体，2025-12 前后）——看行业如何描述瓶颈。
2. **学术议程扫描**（综述、会议议题）——看"记忆 / 一致性"是否被当作开放问题。
3. **现有方案扫描**（生成侧一致性、文档 / 提示词、大模型逐句校准、剧本软件 / 剧集 bible）——逐个标注覆盖层级。
4. **自有实验**——把假设变成可测指标：在真实剧本上度量"无源使用"的规模。
   *这一步属于调研本身：若测出接近 0，说明痛点被高估，项目应当收缩。*

### 1.3 局限（先说清楚）

- 无一手访谈 / 问卷，需求侧证据均为二手；
- 公开材料集中在"画面一致性"，直接论述"台词层知情一致性"的极少——这本身也是 Q2 的答案之一；
- 部分学术材料只到标题 / 摘要级（已逐条标注）；
- 两个检索来源属同一时间窗、同一技术叙事，可能存在共同的信息回声。

## 2. 证据清单

### E1 ·「一致性」被称为 AI 短剧商业化的瓶颈（全文级）

**证券时报 · 21世纪经济报道，2025-12-16《AI视频进入"连续叙事"时代："一致性"成商业化发展瓶颈》**
> "真正的挑战并不在一帧画面的逼真度，而在十集、二十集剧情推进中——角色是否『还是那个人』？场景是否『仍在同一个世界』？"
>
> "观众可以容忍一集画质稍逊，却无法接受主角在第二集『换脸』，或关键道具凭空消失。而『主体不一致』问题，在多集内容中被急剧放大，成为制约AI短剧商业化的瓶颈。"

- 出处：<https://stcn.com/article/detail/3542006.html>
- **能证明**：多集一致性被视为商业化门槛；痛点不在单帧质量，而在"连续叙事"。
- **不能证明**：它讲的是**画面主体**一致性，不涉及"谁知道什么"。

### E2 · 长内容的失败模式被归因为"记忆"问题（全文级）

**36氪，2025-12-25《攻克长视频生成记忆难题：港大与快手可灵 MemFlow……告别快速遗忘与剧情错乱》**
> "一个角色暂时离开画面后再次出现，却『面目全非』，仿佛换了演员……这种『金鱼记忆』式的顽疾，正是长视频生成在叙事上的一大致命伤。"

- 出处：<https://www.c114.net.cn/industry/47554.html>
- **能证明**：主流解法把一致性归因为"记忆机制"；"金鱼记忆"是公认失败模式。
- **不能证明**：其"记忆"指视觉记忆（形象、场景），不含角色的知识状态。

### E3 · 制作方从"观众买单"角度确认代价（全文级，同 E1 转引）

商汤 Seko 产品负责人王子彬：
> "一旦这些要素断裂，观众便会因违和感而脱离剧情沉浸，就不愿意为这样的场景买单。"

- **能证明**：一致性断裂 → 观众流失 → 商业损失，链条被从业者亲口描述。
- **不能证明**：他谈的仍是人物 / 场景一致性；"知情穿帮"造成同类损失需要本文 §3.2 另行推导。

### E4 · 学界把长叙事一致性列为开放问题（摘要级）

检索到的相关议程（**仅见标题 / 摘要级信息，未逐篇精读**）：
- *A Survey on Long-Video Storytelling Generation: Architectures, Consistency, and Cinematic Quality*（IEEE，2026）——把 Consistency 与 Cinematic Quality 并列为长叙事生成的核心维度；
- ICML 2026 · *DynaMem: Consistent Long Video Generation via Hierarchical Memory and Motion Priors*；
- DASFAA · *Improving Multi-turn Dialogue Consistency with Self-Recall Thinking*。

- **能证明**：一致性与记忆是持续的研究议程，不是厂商营销话术。
- **不能证明**：这些工作同样面向画面与对话自洽，仍无"跨集知识状态"这一层。

### E5 · 这一层在真实剧本里的规模（自有实验，可复现）

在两本**零标注**专业剧本上跑同一套规则（剧本本身自洽 ⇒ 报出的每一条都计入误报）：

| 剧本 | 规模 | 报出 | 使用点 | 误报率 |
|---|---|---|---|---|
| 《茶馆》（话剧，72 场） | 258 命题 | 7 | 269 | **2.6%** |
| 《竇娥冤》（元杂剧，18 分场） | 94 命题 | 7 | 165 | **4.2%** |

- **能证明**：「角色引用自己没被交代过的事」这一形态在真实剧本中存在，**可度量**，量级 2–4%；也说明它是**低频但高代价**的问题。
- **不能证明**：这 7 条是否都被编剧视角认同为真错（其中含"公众已知事实"这类应放过样本）——所以产品把 `waive` 豁免做成一等公民。

## 3. 现有方案扫描：覆盖到哪一层

### 3.1 四类做法

| 做法 | 解决什么 | **不解决什么** | 为什么不够 |
|---|---|---|---|
| 生成侧一致性（角色锁定、视觉记忆、long-video memory） | 脸 / 服装 / 道具 / 场景不漂移 | **台词层"该不该知道"** | 保证"看起来是同一个人"，不保证"说的话符合她此刻的认知" |
| 文档 / 提示词 / skill 约定 | 把设定与规则告诉模型 | 无强制点，也无法验证"读没读" | 落笔那一刻没有可执行判断，全靠自觉 |
| 大模型逐句校准 | 用模型读完全本再判断 | 复现性、成本、可审计性 | 上下文随集数增长；同问可能两答；结论不落盘，无法解释"为什么拦这一条" |
| 剧本软件 / 剧集 bible | 人写、人查、版本管理 | 无法自动判断某句台词是否越界 | 结论停留在人脑，规模化后必然漏 |

### 3.2 为什么"知情层"的代价被低估

- **观众侧**：画面不一致 → "这演员换了"（出戏，容忍度尚可）；知情不一致 → "她怎么知道的？"（**觉得被糊弄，直接弃剧**）。
- **制作侧**：画面问题可局部重生成；知情问题往往牵动情节逻辑，**改一集要重写整条线**（第 27 集错，前 20 集埋的伏笔全废）。
- **放大机制**：集数越多，人工记忆越不可靠——而这正是短剧 / 漫剧的核心形态（几十集、边写边拍）。

> 推论：**知情层是"低频、高代价、随规模放大"的问题**。这类问题最适合由常驻基础设施解决，而不是靠提醒或人工检查。

## 4. 需求推导：三条同时成立 ⇒ 产品应当存在

| 必要条件 | 支撑 | 是否成立 |
|---|---|---|
| ① 问题真实且被外部承认 | E1–E4 | ✅（外部承认的是"一致性"，本文做了层级细分） |
| ② 现有方案不覆盖知情层 | §3.1 逐条 + E5 量化 | ✅ |
| ③ 存在可行的独立形态 | 原型已验证（下） | ✅（原型级，非规模验证） |

**③ 的原型证据（同一仓库可复现）**：
- 判据可落盘：建账 23 场约 14 秒，之后 `check` **0 次模型调用**、毫秒级返回；
- 可复现：四类版本戳 + 冻结基线，dev 复跑 0 次判定、结果逐字一致；
- 可挂载：DSH / Claude Code 真连；空目录 `npx -y ./tgz` 可装可跑，6 个工具可用。

**结论**：问题真实、现有方案留空、独立形态可行 —— **该产品应当存在，且形态应是"账本 + 挂载点"，不是"更强的生成模型"。**

## 5. 反证与边界（什么情况下这个产品**没必要**）

- 单集、短时长、非连载：一致性压力小，人工记得住；
- 已有被严格执行的"人物档案 + 时间线"，且写手 ≤1 人：人能兜住；
- 只需要画面一致、不在乎台词层逻辑：生成侧方案已足够；
- 若 E5 的报出率在更多剧本上降到 ~0：说明痛点被高估，项目应收缩为"一次性审计工具"，而非"常驻账本"。

## 6. 把调研结论变成可测指标（承接下一轮）

| 假设 | 指标 | 当前值 | 目标 |
|---|---|---|---|
| 知情穿帮在真实剧本中可度量 | `real` 误报率（两本专业剧本） | 2.6% / 4.2% | 保持 ≤3% 且清单可解释 |
| 账本能拦住"换了说法"的泄漏 | 幻影集 phantom 召回 | 1/8 | ≥5/8（下一轮主线） |
| 误报可被治理而非堆积 | `should_allow` 桶 | 三次尝试被否 | 至多再试一次，不通过则收手 |
| 规模化可用 | 200 场建账耗时 | 23 场约 14s | 200 场 ≤3 分钟且可增量 |
