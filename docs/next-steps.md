# 下一步工作单（`docs/handoff.md` 的补充）

> `handoff.md` 讲**是什么、现在多少、纪律是什么**；本文只讲**接下来做什么、什么顺序、怎么验收**。
> 两份一起读；冲突时以 `handoff.md` 的数字与纪律为准（本文不重复抄数字）。

## 0. 一页速查

红线三条，任何时候都不许越：

1. 真实剧本误报（`real`，茶馆 72 场零标注）**+2 条即回退**，且只在**同一份冻结账本**上比较；
2. dev 的 P/R/cost 不能退；
3. 比例指标必须带 95% Wilson 区间；配对比较用 McNemar，不一致对 <6 不下结论。

三套数字**互不可比**（测试集或判定 provider 不同）：dev（`leaks@1`）· real（茶馆冻结账本）· 跨剧本 holdout（`leaks-jiuzhang@2`）。
跨集只比「各自与自己上一版」的差值。

```bash
npx tsc --noEmit                     # 每次改动后
npm run mcp:smoke                    # 产品路径八步（≈25s，会重建 .ledger）
npx tsx eval/run-r1.ts               # dev（走缓存）
```

## 1. 顺序（有依赖，不要跳）

```
P0 交付面  ① 录屏  ② npx 可装  ③ 真客户端实测        ← 决定「能不能交」，不依赖任何实验
P1 能力面  ④ 归并粒度  ⑤ should_allow 类规则          ← ④ 必须等判定 provider 固定
P2 工具债  ⑥⑦⑧⑨⑩ 见 §2.3                          ← 低风险，可并行
```

**为什么 P0 在前**：面试交付的硬要求是「线上链接 + 仓库 + 5 分钟录屏 + 一条路径走通」，
前三项已完成，缺的是录屏与「别人真能装上再连一次」。精度再涨 1pp 也换不来这两项。

**为什么 ④ 在 ⑤ 之前**：回合 30 的跨剧本集已经测出瓶颈 —— 10 条漏报里 8 条命中，其中 **7 条同一机制**
（注入的泄漏台词被抽成**一条新命题**，于是「首见场景在场者得知」当场给泄漏者发了许可）；
5 条误报里 4 条也同源（同一事实被拆成两条命题）。**这是当前最大的 headroom，不是规则数量问题。**
但它必须先把判定 provider 固定下来（JEV 地区封锁 451，见 `handoff.md` §8.9），否则实验做在降级噪声上。

## 2. 逐项：为什么 / 怎么做 / 验收

### 2.1 P0-1 录屏（≤5 分钟）

**为什么**：硬要求；也是唯一能让评审在不解压仓库的情况下看懂「它拦住了什么」的东西。

**分镜（照这个时间轴录，别临场想）**

| 时间 | 内容 | 素材 |
|---|---|---|
| 0:00–0:40 | 问题：一句「角色说了她还不该知道的事」的硬伤，为什么重做成本高 | 一页纸讲清，不演示 |
| 0:40–2:00 | 真路径：`npm run mcp:smoke` 现场跑，停在「拦住 / 放过 / 豁免」三处 | 终端 |
| 2:00–3:20 | 演示页三个 tab：拦住、放过、命中 2 条但已知情；再点开审计清单与账本词条 | https://kbkb628.github.io/ledger/ |
| 3:20–4:20 | 在真实 agent（DSH 或 Claude Code）里写一句台词，`ledger_check` 当场拦住 | 与 P0-3 一起做，同时产出证据 |
| 4:20–5:00 | 数字与限制：判定层 44/48、真实剧本 4/241、已知误报与 `ledger_waive` 的作用 | 演示页 KPI |

**验收**：≤5 分钟；不装环境的人能说出「它拦住了什么、凭什么拦」；不出现「密钥/绝对隐私路径」。

### 2.2 P0-2 `npx -y` 可装、P0-3 真客户端实测

**为什么**：现在只能在本仓库里 `tsx src/mcp/server.ts`。产品的整个卖点是
「挂到你**自己的**剧本 agent 上」，没有一个能装的包，这句话就没有证据。

**怎么做**

1. 打单文件：`esbuild src/mcp/server.ts --bundle --platform=node --format=esm`（保留 shebang），输出 `dist/mcp.js`；
2. `package.json`：`bin: { "ledger-mcp": "dist/mcp.js" }`、`files: ["dist"]`、版本号；
3. 本地验证：`npm pack` → 在**空目录**里 `npx -y <tgz> ` 起 server → `listTools` 应返回 6 个工具 →
   跑一次 `ledger_ingest`（小剧本）+ `ledger_check`；
4. 接真客户端：DSH 的 `mcpServers` 配置一段、Claude Code 的 `claude mcp add` 一行；
5. README 增一节「实际接入」，贴配置与一次真实拦截输出。

**验收**：空目录可装可跑；两个客户端各留下一次真实调用的配置与输出；
`LEDGER_HOME` 默认 `cwd/.ledger` 的行为在包外仍然成立；两个 key 的 env 名写进 README（不要贴真 key）。

### 2.3 P1 能力面（一次只做一件，且必须进实验库）

| # | 事项 | 怎么做（方向，不是定论） | 验收 |
|---|---|---|---|
| ④ | 跨剧本集的归并粒度 | 让「泄漏现场新建的命题」与既有命题做一次场景内合并（`seed` 已有；`buildUsages`/`merge` 的 blocking 也要看），或在 `detectLeaks` 里对「仅泄漏者在场时新建的命题」降权。**先固定 provider** | 同 provider 前后比 holdout P/R（带 Wilson）；dev 不退；real 不 +2 |
| ⑤ | `should_allow` 类规则 | `real` 剩的 4 条里 2 条是「公开事实」。**回合 31 之后它变成了 ④ 的前置**：许可层收紧在 dev 上 +2 TP，在 holdout 上却 +3 FP，新增误报全是「说话人本人的披露式自证」与「前提性知识」（重生者预知）。方向：自陈来源标记（台词里有「跟我说/告诉我/我亲眼」）+ 前提性知识（按角色声明），都做成 `should_allow` 而不是放宽规则 | real 下降且 dev 不退；holdout 的 13 条 `must_not_flag` 不能被新规则打破 |

### 2.3.1 轮次 31 的结论（已回退，别重做）

`R1_NO_SELF_ESTABLISH=later`（只在「该命题在更晚场次里他也在场」时收回自证）在 dev 冻结上游下
P 3/6→5/8、R 30%→50%、误报仍 3，新抓到的正是 L-02/L-05 两条**时序**泄漏 —— 机制成立。
但 holdout（`leaks-jiuzhang@2`）只 +1 TP 却 **+3 FP**，判据 fp≤5 未过，已回退默认关闭。
`R1_MERGE_EXACT`（逐字相同说法强制归并）在 dev 上只触发 1 次、指标不变，同样默认关闭。
详见 `experiments/exp-031.json` 与 `docs/rsi-round.md` 轮次 31。

## 3. 不要做的事（都会浪费时间）

1. **不要随手跑** `npx tsx eval/regression.ts --k 3 --force-save`（30 分钟起）。
2. **不要往主抽取 prompt 加字段**（`established` / `patients` / 另一处，三次都变差）。
3. **不要跨抽取比 `real`**（重抽两次 = 5 条 / 4 条，噪声 ≈ 红线量级），**不要跨集比 P/R**。
4. **不要在判定层降级状态下做实验**（JEV 451 会静默降级；`judgeWatch` 已改为降级即中止 —— 不要为了「跑完」把它关掉）。
5. **不要在 holdout 上反复调参**：解封一次就记一次（写进 `docs/rsi-protocol.md` 的回合记录），
   同一条 holdout 被用来选版本超过 2–3 次，它的密封性就没了。
6. 不要把 `.env` 里的 key 贴到对话或提交里。
