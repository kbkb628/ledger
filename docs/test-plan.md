## 1. P0｜效度因素（必须先做）

### P0-1　候选排序敏感性　⚠️ 最高优先

**为什么**：论文明确记录 JEV 有**顺序敏感性**（95 次翻转中 3 次置信度 ≥ 0.9）。而我们的候选按召回顺序固定排列，**从未验证「换顺序是否改变结论」**。

若敏感 → 91.7% 含运气成分，且直接冲突于 design.md 的「判决必须冻结、不可重算」。

**怎么测**：把 gold 在候选列表中的位置轮换（首 / 中 / 末），至少 3 种排列，各跑 2 次，比较准确率。

**通过标准**：波动 < 3pp。否则需在实现里固定排序规则（如按 salience / 按 id）。

**状态**：✅ **已完成 —— 未通过，存在排序敏感性**

**实测结果**（JEV，每模式 2 次）：

| 排序模式 | 准确率 |
|---|---|
| recall（按召回相关性） | 91.7% / 91.7% |
| gold-first | 91.7% / 91.7% |
| gold-last | 91.7% / 91.7% |
| sorted（字典序） | 91.7% / 91.7% |
| **reversed（逆序）** | **89.6% / 87.5%** |

**三点解读**：

1. **敏感性存在** —— 逆序使准确率下降 4.2pp，超过 3pp 阈值
2. **但不是「位置偏好」** —— gold 在首/中/末、或字典序，结果**完全一致**，模型不偏向某个位置
3. **「相关性顺序」本身携带信息** —— 召回顺序按实体词匹配强度排（强相关在前），逆序把弱相关干扰项提前，故变差

**由此确立的设计决定**：
> 候选必须**按相关性稳定排序**（不得使用字典序、逆序等无意义顺序），
> 并**在判决记录中冻结该顺序** —— 与「判决不可重算」同源：顺序影响结论，故顺序是判决的一部分。

**实现落点**：`src/ledger` 的候选视图需携带稳定排序键；评测侧保留 `EVAL_ORDER` 以便回归。

### P0-2　干扰项的语义距离

**为什么**：当前候选是「实体词匹配 + 按 object/type 补足」，干扰项与 gold 的距离**不可控**。若太远则题目过易，太近则可能无解 —— 两轮实验的准确率都受此影响却从未量化。

**怎么测**：为每样本计算「干扰项与 gold 的最大相似度」（type/object 重合度，或 embedding 余弦），按相似度分档看准确率。理想是单调（越像越难）；若出现反直觉，说明候选构造有问题。

**状态**：✅ **已完成 —— 候选构造合理，但难度上限偏低**

**实测结果**（JEV，按「干扰项与 gold 的最大相似度」分层）：

| 干扰强度 | 准确率 |
|---|---|
| 0（干扰项与 gold 无关） | 11/11（**100%**） |
| 1 | 17/19（89.5%） |
| 2 | 16/18（88.9%） |
| **3+（高度相似）** | **无样本** |

**两点结论**：

1. ✅ **分布单调** —— 干扰项越像，准确率越低（100% → 89.5% → 88.9%）。
   说明候选构造**合理**，准确率不是「干扰项太远」造成的虚高。
2. ⚠️ **难度上限只有 2，没有任何 3+ 样本** —— 当前黄金集**缺少「同类型 + 同客体 + 同施事」的高混淆题**。

**由此产生的含义**：

> **91.7% 是个偏乐观的数字。** 真实场景中「同一客体、多条同类命题」的混淆
> （如 F-002 / F-009 / F-010 都围绕「遗嘱」）会比当前测试更难。

**触发新增待办** → 见 P1-3。

## 2. P1｜优化因素（预期收益高）

### P1-1　上下文丰富度

**为什么**：当前只给 mention 所在的**一句**。而模糊指代的线索常在**前一句** —— 这一点已在 G-019 上手动验证过（补回前一句后模型就答对了）。`vague_pronoun` 当前 90.5%，是最大的一块可提升空间。

**怎么测**：context 从「一句」扩到「前后各一句」→「整场」，三档对比。

**预期**：`vague_pronoun` 提升；输入变长但 JEV 按 input token 计费，成本仍极低。

**状态**：✅ **已完成 —— 决定性提升，但黄金集随之饱和**

**实测结果**（JEV，`JEV_CRITERIA_MODE=keywords`，上下文三档）：

| 上下文 | 准确率 | vague_pronoun | 延迟中位 | 1000 次成本 |
|---|---|---|---|---|
| 一句（原基线） | 44/48（91.7%） | 19/21（90.5%） | 234ms | $0.0446 |
| **前后各一句** | **48/48（100.0%）** | **21/21（100.0%）** | 230ms | $0.0457 |
| 整场 | 48/48（100.0%） | 21/21（100.0%） | — | — |

**三点结论**：

1. ✅ **一句话的上下文是最大的单点瓶颈。** 扩到「前后各一句」后，
   全部错误清零（含 2 条 `NEW`、2 条 `UNSURE` 的负例也对）。
2. ✅ **成本几乎不变**（+2.5%）：JEV 按 input token 计价且单价极低，
   上下文变长几乎不花钱 —— 这与「用大模型做判定」的成本直觉相反。
3. ⚠️ **黄金集饱和了。** 连续 3 轮全部 48/48，分层统计全档 100%
   （干扰强度 0/1/2 档均满分）。**从此这个集子无法再区分任何配置。**

**由此产生的两个后果**：

- **P1-3（补充高难度样本）升为最高优先** —— 没有更难样本，P1 的剩余项
  （指令措辞、候选数量、few-shot、选项命名）**都无法测出差异**。
- **P0-1（排序敏感性）的结论需要用新集复验** —— 当时的 −4.2pp 是在 91.7% 的
  难度下测得的；饱和后排序可能不再敏感，但不能据此认为产品里可以不冻结顺序。

### P1-2　结构化字段的消融实验

**为什么**：我们一直把 `agent / patient / object / timeRef` 全给，但**没测过去掉某个字段会降多少**。做一次消融，就知道抽取层哪些字段值得抽、哪些是白费功夫 —— **直接省下抽取层的实现成本**。

**怎么测**：逐个去掉单个字段，看准确率变化；再试「全去掉」看基线。

**状态**：✅ **已完成 —— 结构化字段对判定零贡献**

**实测结果**（JEV，`JEV_CRITERIA_MODE=keywords`，逐个去掉字段）：

| 配置 | 准确率 |
|---|---|
| baseline（全字段） | 44/48（91.7%） |
| −type | 44/48（91.7%） |
| −agent | 45/48（**93.8%**） |
| −patient | 45/48（**93.8%**） |
| −object | 44/48（91.7%） |
| −timeRef | 44/48（91.7%） |
| **−全部结构化字段** | 45/48（**93.8%**） |

**结论**：

1. **去掉全部结构化字段，准确率没有下降**（+1 条样本，属统计噪声）。
2. 原因很直接：`type/agent/patient/object/time_ref` 都是 canonical 散文的**派生冗余**
   —— 「苏婉伪造了遗嘱」这句话里已经含有施事、客体、类型。
3. 与 v2（`distinguisher` ±0pp）是同一个规律的第三次验证：
   > **有效的不是「结构化」，而是「保留字面线索」。**

**对抽取层的含义（重要）**：

> **结构化字段是「索引」，不是「证据」。**
>
> - 作为**判定输入** → 0 贡献，可以不喂。
> - 作为**召回 / 事件同一性 / 影响传播**的键 → 仍然必需
>   （`recallCandidates` 依赖它、P0-2 的干扰强度依赖它、账本的依赖图更依赖它）。
>
> 抽取层的**硬产出**只有两样：**canonical 命题表述** + **典型表述（keywords/别名）**。
> 其余字段按「下游谁要谁负责」的次序做，做不出来不阻塞判定链路的打通。

**一个必须记下的不一致（P2-1 的入口）**：消融时用的判定指令仍在说
「线索优先级 1. 上下文中的实体词直接命中候选的 **agent / patient / object**」，
**而这些字段恰好被我们去掉了** —— 模型面对一条指不到任何字段的指令，
依然拿到了 93.8%。

> 这**加强**了结论（模型确实靠散文 + 典型表述），但也说明：
> 消融不是「受控地抽掉信息」，而是「抽掉信息后模型自己找了替代线索」。
> 指令措辞与实际输入的这一处错位，应作为 P2-1 的第一个实验对象。

### P1-3　补充高难度样本（**由 P0-2 触发，P1-1 后升为最高优先**）⚠️

**为什么（原）**：P0-2 发现当前候选的干扰强度**上限只有 2**，缺少 3+ 的高混淆题。
现有准确率因此偏乐观，无法反映真实场景（同客体、同类型、同施事的命题并存）。

**为什么（P1-1 后加强）**：P1-1 把准确率推到 **100%（连续 3 轮）**，
黄金集**彻底饱和** —— 分层统计全档满分、级联接受集 100%、剩余错误为 0。

> **这是一个测量工具失效的问题，不是好消息。**
> 饱和之后，P1 剩余的每一项（指令措辞、候选数量、few-shot、选项命名、泛化黑白洞）
> 都**无法测出差异**；P0-1 的排序敏感性结论也无法复验；100% 更无法说明
> 「产品在真实剧本上准确率是多少」。

**怎么补**：两条并用。

1. **加高混淆命题**：在同一施事 / 同一客体上放**多条不同类型**的命题
   （如「苏婉**伪造**遗嘱」与「苏婉**销毁**遗嘱」），使相似度进入 3+ 档。
2. **加难指代**：把部分 mention 的线索**只留在两行以外**，或让相邻行含有
   诱导性关键词，使「前后各一句」不再够用。
3. **加负例**：更多 `NEW` / `UNSURE`，尤其是「看起来像某命题但其实是新的」。

**验收**：准确率**回落到 80–95% 区间**（有区分度），且分层统计重新出现梯度。

**状态**：✅ **已完成（由黄金集 v3 重标解决，见 §5.5）**

> 结论：不是「补几条更难的样本」，而是**粒度错了**。把 F-001 拆成
> 「未施救 / 争执 / 落水」三条后，3+ 干扰强度档自动出现 13 条样本，
> 准确率回落 91.7%，区分度恢复。**手工造难题是最后手段，先查粒度。**

### 5.1 B-1 抽取层 v0 的对拍结果（`npm run eval:extract`）

抽取层已能跑通，并用**同一剧本的黄金集**验收（14 命题 / 37 别名，无需新标注）：

| 指标 | 结果 | 读法 |
|---|---|---|
| **原文可查拦截** | **0 条** | ✅ 说法 100% 在原文里 —— 没有重演「手写关键词」的效度事故 |
| **首见场景正确** | 16/17（94.1%） | ✅ 时序过滤的基础可靠 |
| 命题召回 | 11/14（78.6%） | 一对一指派后的诚实数字 |
| 别名召回 | 17/37（45.9%） | 精确 8 + 包含 9 |
| 过抽取 | 抽出 24 条 vs 命中 11 条 | 含真实错并 |
| 速度 / 成本 | 23 场 **32.8s** / **$0.034** | 关思考模式后比开思考快 **25×**、便宜 **11×** |

**⚠️ 最重要的发现：失败模式不是「抽漏」，是「错并」。**

模型把**不同场次、不同事件**的说法挂到了同一条命题上：

```
E-005  苏婉让陈默处理掉沈父留下的那份东西
   → 同时匹配 F-002/F-005/F-006/F-008/F-009/F-011
   说法：「老爷留下的那份东西，还在你手上？」
         「处理掉。烧了，别留痕迹。」
         「那份东西要是没了，谁也不知道是你经手的。」
         「那笔钱，那份假遗嘱，还有那份婚约——都是你做的」
```

**它用「说法相似」当归并依据，而不是「事件同一性」。** 这正是 `design.md` 预言的失效模式
—— 只不过发生在**抽取层内部**，而不是判定层。

**原因是架构性的，而且设计文档早就写了**：v0 的抽取指令把**抽取**与**归并**塞进了同一次调用
（prompt 里给了「已抽出的命题清单」，让模型自己决定 ref 是否 `NEW`）。
而设计的三层路由明确要求二者分离：

> 第 0 层抽取（场内，**不做跨场归并**）→ 第 1 层结构匹配 → 第 2 层 JEV 判定 → 第 3 层人工

**结论：这一轮实验反向验证了「抽取与归并必须分离」这个设计决策。**

**v0 已确立可用的部分**（不要推翻）：

- `canonical` + `surface` 两字段的最小范围可行（P1-2 的结论成立）
- 「原文可查」的代码校验有效，且**不损失召回**（拦截 0 条）
- `first_seen` 可直接从抽取顺序得到
- 关掉思考模式更快**也更准**（24 条 vs 52 条，粒度更接近 golden）

**v1 要改的**：

1. **抽取只做场内**：去掉 prompt 里的「已有命题清单」，禁止跨场归并
2. **归并独立成层**：复用已验证的 JEV 判定（100%），而不是让抽取模型顺手做
3. **区分明确指称与泛化指代**（`reference_kind`）——
   「两千三百万」是明确指称，「那份东西」是泛化指代；**后者是错并的唯一入口**，必须单独标记

### 5.2 v1 / v2 / 端到端：三次迭代撞上同一个根因

| 版本 | 改动 | 别名召回 | 场内命题数 | 结论 |
|---|---|---|---|---|
| v0 | 抽取 + 归并同一调用 | 17/37（45.9%） | 24 | 模型按「说法相似」错并（E-005 吃掉 6 条） |
| v1 | **归并移出抽取层**（独立 JEV 归并 + `reference_kind`） | 15/37（40.5%） | 39 | 错并止住；但别名去向三分类暴露新问题 |
| v2 | **定义粒度**（一条命题 = 可被知道或不知道的客观事实） | 14/37（37.8%） | 32 | 清掉了「某人知道了…」这类伪命题，指标未改善 |

**v1 的别名去向三分类**（37 条 golden 别名）：

| 去向 | 数量 | 逐条核查后 |
|---|---|---|
| ✅ 挂对 | 15（40.5%） | 真正确 |
| ⚠️ 抽到了但挂到别的命题 | **16（43.2%）** | **几乎全不是错误，是粒度不一致** |
| ❌ 根本没抽出 | 6（16.2%） | 真漏抽 |

「挂错」那 16 条的真相：

- F-001「码头那天」→ 挂到 E-004 —— **E-004 就是 F-001**，只是贪心指派把它分给了 F-014
- F-002「那份假遗嘱」→ E-028「苏婉伪造了假遗嘱」—— golden 的 F-002 是「**伪造并调换**」，抽取拆成两条
- F-005「你和苏婉的婚约」→ E-016 —— golden 的 F-005 是「伪造的备忘录」，抽取拆成三条

### 5.3 端到端：**这才是产品的真实指标**（`eval/run-e2e.ts`）

拿抽取出来的账本（不是人工构造的）去回答黄金集的 48 个 mention：

| 指标 | 值 |
|---|---|
| **端到端准确率** | **19/48（39.6%）** |
| 基线（人工账本 + JEV） | 48/48（100%） |
| 其中「不可答」 | 6 条（gold 命题完全没被覆盖：F-004/F-007/F-013/F-014） |
| explicit_noun | 10/22（45.5%） |
| repeated_surface | 1/5（20.0%） |
| vague_pronoun | 8/21（38.1%） |
| 成本 / 延迟 | $0.0014 / 11.0s（48 条） |

**粒度切分诊断**（一条 golden 命题匹配到几条账本命题）：

```
0条→2个命题   1条→3个   2条→5个   3条→4个
```

**14 条 golden 命题里，9 条被拆成了 2–3 条账本命题。**

### 5.4 结论：粒度是产品的隐含核心变量，而它从未被定义

> **39.6% 不是产品的准确率，它是在度量「粒度不统一」这个未定义变量。**
>
> 一条 golden 审计单元被拆成 3 条账本命题时，采样指到「映射的那一条」的机会**最多 1/3**
> —— 39.6% 是**下界**，不是产品的真实水平。

**这个变量同时决定了五件事**，而它们此前被当成五个无关的问题：

| 它决定 | 此前的表现 |
|---|---|
| 抽取层输出规模 | v0 抽出 52 条 vs golden 14 条 |
| 归并层判定难度 | v0 的 E-005 错并 |
| 候选集干扰强度 | **P0-2 的「难度上限只有 2」** |
| R1 的审计单元 | `mind(C)` 里的元素是什么 |
| 依赖图 / 重做代价的节点 | 改一处影响哪些产物按什么粒度算 |

**架构缺口**：`design.md` 的三层路由是「第 1 层结构匹配 → 第 2 层 JEV 判定」，
**两层都只做「是不是同一件事」，没有任何一层做「把多条细事实提升成一个审计单元」**。

所以需要一个设计里没有的层：

> **第 0.5 层 归并（promotion）：细粒度事实 → 审计单元**
>
> 判据不是「同一件事」（那是第 1/2 层），而是「**是不是同一个秘密/同一个可被知道的事实**」。
> 例：「苏婉伪造遗嘱」+「苏婉调换遗嘱」→ 一个审计单元「苏婉篡改了遗嘱」；
> 但「陈默持有遗嘱原件」是**另一个**审计单元（不同的人、不同的可被知道的事实）。

**两条可选路线**（需要决策）：

1. **账本向 golden 靠**：新增 promotion 层，把细事实归并成审计单元。
   产品上正确 —— R1 要的就是审计单元，依赖图也不该有「陆见深站在岸边」这种节点。
2. **golden 向账本靠**：按「客观事实」的自然粒度重标 48 个样本的 gold。
   代价是要重标，而且会失去「审计单元」这个产品语义。

**在统一粒度之前，端到端数字不能作为产品指标对外使用。**

### 5.5 黄金集 v3：重标之后，干净基线到手（**同时解决了 P0-2 与 P1-3**）

按「一条命题 = 一个角色可以知道或不知道的客观事实」重标：**14 条 → 18 条**，48 样本不变。

拆分三处（其余刻意不拆）：

| v2 | v3 | 理由 |
|---|---|---|
| F-001 码头事件 | **F-001** 未施救 · **F-015** 争执 · **F-016** 落水 | 三个不同施事/主体，剧本是三句独立叙述 |

#### 重标顺带修掉了 v2 的 4 个无效样本

这是一类待补的样本，不是可以糊弄过去的。

粒度切分仍有残留（18 条 golden 里 10 条对应 2–4 条账本命题），
所以 **56.3% 里既有真漏抽，也有残留粒度差** —— 下一步的 promotion 层正是冲着后者去的。

### 5.6 Promotion 层：先量收益上限，再决定建不建

在动手前先给端到端加**失败分类**（`eval/run-e2e.ts` 的 `diag`），把 21 条未命中拆开：

| 类别 | 条数 | 含义 |
|---|---|---|
| `uncovered` | 6 | gold 命题在账本里无对应 → 抽取/归并真漏 |
| `recall_miss` | **0** | blocking 完好，不是候选召回的问题 |
| `judge_negative` | 7 | 判定选了 `NEW`/`UNSURE` → 判定层在抽取账本上退缩 |
| `judge_same_unit` | 7 | 判定选了**同一审计单元**的另一条 → 粒度问题 |
| `judge_other` | 1 | 选了别的审计单元 → **真正的语义错误只有 1 条** |

> **结论：账本里的命题本身基本是对的**（跨单元语义错误只 1 条），
> 剩下的差距一半是粒度、一半是漏抽与判定退缩。**promotion 的收益上限 = 7 条 = +14.6pp。**

#### 实测（`src/extraction/promote.ts`，一次聚类而非两两判定）

| 配置 | 命题级 | 审计单元级 | 成对精确率 | 成对召回 |
|---|---|---|---|---|
| 无 promotion（用 golden 分组） | 56.3% | 34/48（70.8%） | — | — |
| promotion v0 | 56.3% | **35/48（72.9%）** | 77.5% | 86.1% |
| promotion v1（更强的反例） | 56.3% | **35/48（72.9%）** | **80.0%** | 77.8% |

**为什么是一次聚类而不是两两判定**：第 1/2 层问「这两条是不是同一件事」（局部可判），
promotion 问「这几条是不是同一个秘密」（需要全剧语境）。代价是不可增量，账本一变要重算
—— 当前规模一次调用 $0.0019 / 0.4s，可以接受。

#### 三个必须记下的坑

1. **单元级准确率会奖励过并。** 分组越粗，误判越容易被算成「同单元」。
   promotion 得 35/48 比 golden 分组的 34/48 还高，不代表它比人工分组好 ——
   **它只是更粗**。所以单元级准确率必须与分群精确率一起看，不能单独引用。
2. **v1 的取舍**：精确率 77.5%→80.0%，召回 86.1%→77.8%，净准确率不变。
   说明继续调 prompt 是零和的，瓶颈不在措辞。
3. **promotion 看不到剧本。** 它只有命题清单（25 条 canonical），却要判断
   「遗言 / 篡改 / 去向 / 销毁」是四个不同的秘密 —— 这需要剧情知识。
   **下一步应把命题所属场景与邻近原文喂进去**，这是有原理的改法，不是继续调措辞。

#### 下一轮该修什么（按 headroom 排序）

| 项 | 条数 | 说明 |
|---|---|---|
| `judge_negative` | 7（14.6pp） | 判定层在**人工账本**上 100%，在**抽取账本**上退缩 7 次 —— 两侧差在 canonical 表述与别名数量上，**可能是最便宜的一仗** |
| `uncovered` | 6（12.5pp） | 抽取层真漏抽（F-004/F-007/F-013/F-014/F-016） |
| promotion 精确率 | — | 喂场景上下文；上限 +8 条（已量化） |

### 5.7 候选补齐协议：14.6pp 的差距来自评测协议本身

追 `judge_negative` 时发现根因**不在判定层**：抽取账本的别名比人工账本稀疏
（44 条说法 / 25 条命题 vs 76 / 18），于是 alias 匹配经常只命中 **1 条**候选。
而 JEV 是 decision-only 的**比较**机器 —— 候选只剩一条时，它把 `NEW` 当成更安全的答案：

```
G-006/007/008 → NEW    候选: E-012(1kw)      ← 只有 1 条候选
G-012         → NEW    候选: E-001(3kw)
G-032         → NEW    候选: E-020(0kw)
```

而 `rsi-log.md` 的**实验纪律第 3 条本来就要求「候选集规模 ≥ 4」** ——
这一条在 `run-eval.ts` 里实现了，`run-e2e.ts` 漏了。**这是评测协议的锅，不是模型的锅。**

#### 补齐策略实测（`E2E_PAD` 切换）

| 策略 | 补齐依据 | 命题级准确率 | 审计单元级 |
|---|---|---|---|
| `none` | 不补（协议缺陷） | 27/48（56.3%） | 31/48（64.6%） |
| `sim` | 字符 bigram 相似度 | 22/48（**45.8%**） | 33/48（68.8%） |
| **`id`** | **命题 id 顺序（中立）← 标准** | **29/48（60.4%）** | **37/48（77.1%）** |

**三种协议相差 14.6pp。** 所以：

> **「端到端准确率」必须连候选补齐协议一起报，单说一个数字没有意义。**

- `none` 会退化成一选一，判定器倾向说 `NEW`
- `sim` 用相似度补，等于**人为加难度**（补进来的干扰项与正确答案最像）
- `id` 中立：既避免退化问题，也不偏向相似，是唯一可复现的中立基线

（另有一条纪律：补齐**绝不能用 gold 的结构化字段**去找相似候选 —— 那是照答案挑把难度压低。）

#### 标准协议下的最终数字（`E2E_PAD=id`）

| 指标 | 值 |
|---|---|
| **端到端 · 命题级** | **28–29/48（58.3–60.4%）**（JEV 非确定性，1 条波动） |
| **端到端 · 审计单元级（promotion 实际产出）** | **37/48（77.1%）** |
| 人工账本基线（同一黄金集） | 44/48（91.7%） |
| promotion 分群精确率 / 召回 | 80.0% / 77.8% |
| 级联接受集 | 20 条 → 18 条正确（90.0%） |
| 成本 / 延迟 | 端到端 $0.0016 / 10.4s；promotion $0.0022 / 0.3s |

**⚠️ §5.6 里的 56.3% / 72.9% 是 `E2E_PAD=none`（协议缺陷）下的数字，已被本节取代。**

#### 标准协议下的失败分类（20 条）

| 类别 | 条数 | 判断 |
|---|---|---|
| `uncovered` | 6 | **最大单项**：抽取层真漏抽（F-004/F-007/F-013/F-014/F-016） |
| `judge_negative` | 5 | 多半仍是别名稀疏导致的退化，不是判定能力问题 |
| `judge_same_unit` | 9 | 单元级下算对（promotion 已兑现） |
| `judge_other` | **0** | 跨单元语义错误已归零 |

> **下一轮的靶子只有两个：抽取层的别名覆盖（uncovered + judge_negative 合计 11 条）
> 和 promotion 的分群精确率。判定层与归并层已经不在关键路径上。**

### 5.8 R1 端到端首次打通：产品路径成立，但误报 75%

`npm run audit` 现在能跑完整条用户路径：

```
剧本 → 抽取（命题 + 知识变化）→ 归并 → usages（说法 + 说话人）→ R1 → 问题清单
```

| 量 | 值 |
|---|---|
| 账本 | 24 条命题 / 38 条说法 |
| 知识变化（`mind` 的来源） | **8 条**（原文可查校验全过） |
| 使用点（说话人明确的台词引用） | **36 处** |
| **R1 报出的泄漏** | **27 条 → 75% 的误报率** |

**一个关键设计收获：`usages` 是免费的。** 抽取层产出的每条 `surface` 就是一个说法，
它带着首次出现的场景；归并后挂在某条命题上 —— **那就是一次 use**。说话人从台词前缀
（`角色：`）直接可得，叙述行没有前缀 → 不是角色的使用。所以 R1 只需要补一个未知量：
`mind(C)`，而它由同一份抽取的 `knowledge_deltas` 顺带产出（同一次调用，不是新链路）。

#### 27 条误报的原因高度集中

| 原因 | 例 | 该怎么修 |
|---|---|---|
| **施事不知道自己做的事** | 苏婉用「那份东西」（就是她下令烧的）；陈默用「那份原件，我一直留着」（就是他留的） | 需要 `agent`：**施事天然知道自己的行为** |
| **职责性知情** | 律师「那份是唯一在册的遗嘱」；财务总监「两千三百万，同一个离岸账户」 | 默认知识层按角色职责 |
| **公开 / 在册事实** | 「我父亲三年前立过一份遗嘱」 | 默认知识层按事实类型 |
| **特殊设定** | 沈知微是重生者，知道前世的事 | 只能从剧本设定来，不能自动推 |

> **封闭世界假设「没记到就是不知道」太粗了。** 必须有「默认知识层」，
> 而它的第一要件是**施事**。

#### 这一轮反过来修正了一个字段分类

P1-2 消融的结论是「`type/agent/patient/object/time_ref` 对判定零贡献，是索引不是证据」。
**这个结论没错，但适用范围被这一轮澄清了**：

| 字段 | 判定层 | R1 的默认知识层 |
|---|---|---|
| `canonical` / `surface` / 宽上下文 | **必需（证据）** | — |
| `agent` | 零贡献 | **必需** —— 施事天然知道自己的行为 |
| `time_ref` / `object` / `type` | 零贡献 | 有用（职责性知情、公开事实的判据） |

> 所以字段不该分两类，而是**三类**：**证据**（喂判定器）、**索引**（召回/同一性/传播）、
> **审计必需**（R1 默认知识层）。`agent` 属于第三类 —— 它从来不是「白费功夫」，
> 只是当初消融测的是另一个层。

**下一步**：抽取层补 `agents`（每条命题的施事与在场者），用它建默认知识层的第一条规则
（施事 ⇒ 知道），再逐条处理剩余三类误报。**误报率是 R1 能否成立的门槛，比绑定准确率更要命。**

### 5.9 默认知识层第一条规则：施事 ⇒ 知道（误报 23 → 18）

抽取层补了 `agents`（施事，含「人名必须原文可查」校验），默认知识层加了第一条规则。

**隔离实验**（同一份缓存，开关 `AUDIT_NO_DEFAULT` —— 否则抽取输出变化会混淆因果）：

| 配置 | 误报条数 |
|---|---|
| 关默认层 | 23 |
| **开默认层（施事 ⇒ 知道）** | **18**（−5，−21.7%） |

当前账本：19 条命题 / 36 条说法 / 33 个使用点 / 知识状态 20 条（抽取 8 + 默认层 12）。

#### 剩余 18 条的成因（已定位到四类）

| 成因 | 例 | 需要什么 |
|---|---|---|
| **职责性知情** | 财务总监「两千三百万，同一个离岸账户」；律师「那份是唯一在册的遗嘱」 | 角色职责表（剧本没有显式声明） |
| **当事人知情**（不是施事） | 陆见深「我从来没签过。那是你伪造的」——他是被伪造的一方 | 需要 `patient`，不只 `agent` |
| **公开在册事实** | 「那份婚约」（全场都知道存在） | 需要事实类型（`type`）区分公开/秘密 |
| **⚠️ 归并失败** | 沈知微在 S13-02 得知「两千三百万」，在 S19-02 引用「那笔钱」——**知识记在命题 A 上，使用引用的是命题 B**，同一件事被拆成两条 | **promotion** |

#### 一条架构结论：**R1 必须跑在审计单元上，不是细命题上**

第 4 类不是漏抽，是**账本粒度与知识粒度的错配**：
知识是关于「那个秘密」的，使用也是关于「那个秘密」的，
而账本把它们切成了多条「客观事实」。

> **所以 promotion 不只是 UX 分组，它是 R1 正确性的前提。**
> `mind(C)` 应该记在审计单元上，`used_at` 也应该算在审计单元上 ——
> 这样「沈知微得知了两千三百万」才能覆盖「那笔钱」这个引用。

这把 promotion 从「可选优化」升级成了**必做项**，并且给了它一个新的、硬得多的验收标准：
不只要求分群精确率，还要求**接上 R1 后误报真的下降**。

**下一步顺序**：① 把 R1 的 knowledge / usage 提升到审计单元层（接 promotion）→ ② 补 `patient`（当事人知情）→ ③ 职责性知情 → ④ 公开事实类型。每步都用 `AUDIT_NO_DEFAULT` 式的开关做隔离实验。

### 5.10 产品形态落地：MCP server（`src/mcp/server.ts`）

按最小实现把产品做成 **MCP server**，不是 Web 应用。理由是用户的原话：
「用户的剧本应该都在他们本地的剧本生成 agent 上」——复制粘贴式 Web 应用从根上不合这个场景。

而 MCP 同时是 **GPT / Claude / Cursor / DSH 的共同形态**，做一次就能挂在各自的本地 agent 上，
不绑死客户端。（`design.md` §10 早就写了「账本做成 MCP server」，这一轮才落地。）

#### 六个工具（刻意克制：工具定义会为每次请求增加 token）

| 工具 | 作用 |
|---|---|
| `ledger_ingest` | 首次建账并**冻结**；重复调用会被拒绝（不变量 1） |
| `ledger_record` | **一场**新戏增量并入，不重扫全本（不变量 2 的落地） |
| **`ledger_check`** | **写完一句台词之前调用** —— 命门 |
| `ledger_audit` | 全剧 R1 清单 |
| `ledger_page` | 读词条（wiki 形态：说法、首见场景、来源、知识、判决流水） |
| `ledger_waive` | 人工豁免，理由进流水 |

#### 落地位置的取舍

```
LEDGER_HOME（绝对路径）  >  <cwd>/.ledger[/<series>]/
├── ledger.json      主账本（人可读、可 diff、进 git）
└── decisions.jsonl  append-only 判决流水
```

**不放 agent 私有目录**，因为账本是**项目资产**（可 review、可协作、换 agent 还在），
而各客户端私有路径没有统一约定，依赖它等于绑死客户端。
每个工具返回值都带 `ledgerPath` —— 否则账本落在哪里用户不知道。

#### 三个来自 DSH 实际配置的硬约束（查 `@deepseek-ai/dsh-mcp-client` 得出）

1. **`toolCallTimeoutMs` 默认 60 秒**，而 `ingest` 跑 23 场要 43 秒 —— **只够两集**。
   所以 `ledger_record`（逐场增量）**是必需项，不是优化**：60 集必须写一场记一场。
2. **MCP 只桥接 tools，不支持 resources / prompts**（README 原文）。所以设计不能依赖这两个原语
   —— 我们全是工具，但这条要写死，免得以后想用。
3. **工具定义会增加每次请求的 token**。所以工具面卡在 6 个，不要因为方便再加。

#### 验证（`npm run mcp:smoke`，用真 MCP 客户端连上去）

```
可用工具 6 个
[1] 无账本时 check → 可操作的错误（含查找位置）
[2] ingest 43s → 21 条命题 / 38 条说法 / 19 条知识 / 23 场
[3] 重复 ingest → 已拒绝 ✓               ← 冻结不变量生效
[4] check「沈知微：你三年前在码头做了什么」→ leak=true
     ⚠️ 「你三年前在码头做了什么」→ 陆见深三年前在码头做了某件事
[5] check「陈默：那份原件，我一直留着」→ leak=false
[6] audit → 19 条
[7] 豁免一条 → 19 → 18 ✓
[8] page E-001 → 说法 1 条 · 知识记录 0 条
```

**第 [4] 步就是产品的命门**：agent 在提交这句台词**之前**被拦住，
而不是写完 60 集再出一份没人看的报告。

#### 还没做（明确记账）

- 审计单元级 R1（promotion 未接进 R1，`auditUnit` 字段已留好但为 null）
- 缺口中的 `patient` / 职责表 / 公开事实类型
- 演示页（面试题要求的「线上链接」）—— MCP 本地跑没有链接，
  需要另做一个只读页展示一次真实审计输出
- 打包发布（`npx -y` 可用的 npm 包）

### 5.11 R1 真阳性度量：精确率 20% / 召回率 33.3%

**必须先有「有真泄漏的剧本」才能度量 R1。** 正本《旧账》内部自洽、一条真泄漏都没有
（18 条报出**逐条判完全是误报**），在上面精确率恒为 0、也无法演示能力。

所以新建 `eval/script-leak.md`（8 场，故意注入 3 处泄漏）+ `eval/leaks.json`（标注）：

| 编号 | 场景 | 谁 | 类型 | 设计 |
|---|---|---|---|---|
| L-01 | S03-01 | 陈立 | 无源 | 提「书房暗格里那份」，但暗格只在 S02-01 私下告诉林昭 |
| L-02 | S01-03 | 林昭 | 时序 | S01-03 就用「暗格里那份」，而她 S02-01 才得知 |
| L-03 | S05-01 | 周管 | 无源 | 「两千三百万经陈立的手走的」，只在 S03-01 何静陈立私下对话出现 |

同时保留 6 条「应当被放过」（当事人 / 亲历 / 当场看到 / **误信** / 本职）。

#### 实测（`npm run eval:r1`）

```
账本 8 条命题 / 12 个使用点 / 11 条知识状态 · 报出 5 条
❌ L-01 漏掉   ❌ L-02 漏掉   ✅ L-03 抓到
精确率 20.0%（TP 1 / 报出 5）　召回率 33.3%（抓 1 / 注入 3）
```

#### 两种失败，两个不同根因

**① 漏掉 L-01/L-02 不是判定逻辑错，是「说法太长」。**
账本里 E-004 的说法是整句「真正的那份遗嘱，在书房暗格里」，
而陈立说的是「书房暗格里那份」、林昭说的是「暗格里那份」——
**双向包含都不成立**，连使用点都没扫到，根本没进判定。

**② 4 条误报里 3 条缺「在场者」规则。**
周管亲历老爷去世、何静本人经手公证、周管自己说的那句 —— 都该算已知。
我之前否掉「在场 ⇒ 知道」是因为它太强；**窄化到「命题首见场景的在场者」就成立**：
一个事实在某场被第一次公开说出来，在场的人就都知道了。

验算它会不会顺手放过真泄漏：

| 泄漏 | 命题首见 | 在场 | 会被放过吗 |
|---|---|---|---|
| L-03 周管「两千三百万」 | S04-01 | 林昭、陈立 | **否** ✓ |
| L-01 陈立「暗格」 | S02-01 | 林昭、周管 | **否** ✓ |
| L-02 林昭「暗格」@S01-03 | S02-01 | 林昭、周管 | 她 S02-01 确实得知，但用在 S01-03 → 时序泄漏 ✓ |

第 4 条误报（何静「两千三百万」被挂到「陈立转走」那条命题上）是**归并错配**，
规则修不了，得靠抽取/归并质量。

#### 下一步（都有实测依据，顺序不能反）

| 步骤 | 改什么 | 预期 |
|---|---|---|
| **1. 抽取记最短指代片段** | surface 改为能指代它的**最短片段**（「暗格」而非整句） | 召回 33% → 期望 100% |
| 2. 在场者规则 | 命题首见场景的在场者 ⇒ 得知 | 精确率 20% → 期望 ~75% |

**先做 1**：召回为 0 时精确率没有意义（一条都抓不到，100% 精确也是废的）。

附带发现：`在场` 一直在场景元数据里（`- 在场：林昭、周管`），
抽取时只顾着 `agents`，**这条零成本的确定性信息一直没用**。
