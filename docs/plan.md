# 计划：先让测量站得住，再继续内核

> 起因是一次自审：**现在的测试模式不符合 RSI。**
> 它是一套有纪律的 eval-driven 迭代，但缺了三样关键东西 —— 以至于「改动有效」和「恰好抖到这里」分不开。
>
> 这份文档记录两件事：**(A) 补完这三件事的计划；(B) 补完之后要接着做的既有计划。**
> 回合纪律见 `rsi-protocol.md`；本文只定「做什么、什么算完成、先后顺序」。

---

## 0. 状态快照（写这份计划时的实测值）

| 层 | 指标 | 值 | 来源 |
|---|---|---|---|
| 判定层 | 准确率（人工账本 + JEV） | **44/48（91.7%）** | 黄金集 v3，3 轮稳定 |
| 端到端 | 准确率（抽取账本 + JEV，命题级） | **29/48（60.4%）** | `E2E_PAD=id` |

| R1 | 误报 | 3 条 / 报出 6 条 | 同上 |
| 成本 | 抽取 23 场 | $0.02–0.05 / 30–43s | — |

已有 RSI 基础设施：`git` 回退、R1 层四个开关（默认=已测最优）、
冻结基线 `eval/baseline/pipeline-leak.json`、7 回合记录。

**缺口（这份计划要补的）**：没有 holdout、没有标量目标、没有联合回归、成因分桶靠人眼。

## A. 补三件（+ 顺手做成因分桶）

### A-1　切 holdout —— 让结论可信的最低成本一步

**问题**：R1 的 10 条标注既用于决策、又用于汇报。任何针对它的调参都是过拟合，而我分不出来。

**做法**
1. `eval/leaks.json` 增加 `"split": "dev" | "holdout"` 字段；标注扩到 **14 条**（10 dev + 4 holdout）。
2. `eval/run-r1.ts` 默认**只报 dev**，并打印一行「holdout 4 条已封存」。
3. 新增 `--holdout` 参数才跑 holdout。**约定：只在「决定要不要翻默认值」时跑，且跑了必须记录。**
4. holdout 的 4 条要覆盖不同成因（1 条无源 / 1 条时序 / 1 条 delta 污染 / 1 条应当放过），不能全是同类。

**验收**：一条命令分别输出 dev 与 holdout 的 P/R；`rsi-protocol.md` 新增约定条目。

**为什么排第一**：它不改变任何实现，却是后面所有结论的前提。

### A-2　定义标量目标 —— 让取舍不再靠拍脑袋

**问题**：精确率 38.5%/召回率 50% 与 50%/30% 哪个好？我现在靠「觉得误报更疼」拍板。

**做法**
1. 定一个成本函数：
   ```
   cost = 误报条数 × C_fp + 漏报条数 × C_fn
   ```
2. **权重必须写清理由，并声明它是假设不是事实**。建议起点：

   | 权重 | 取值 | 理由 |
   |---|---|---|
   | `C_fp` | 1 | 一次人工复核 ≈ 打开原句、判断、写豁免理由，约 1 个单位 |
   | `C_fn` | 3 | 漏掉一次知识泄漏 ≈ 一场戏返工，约 3 个单位 |

   `C_fn=3` 与「误报更疼」并不矛盾：**误报之痛在于它会让人关掉工具**，
   这一点在权重里体现不出来，所以另加一条**硬约束**：`误报率 > 70%` 直接判不可用，
   不论 cost 多低。

3. `run-r1.ts` 输出 `cost`；回合表的判定列改为看 cost。
4. 权重写进代码常量并在输出里回显，方便事后调整时对照。

**验收**：所有回合的判定都能用一句 `cost` 解释；第 7 回合的 ⏸ 能被 cost 重算验证。

### A-3　联合回归 —— 防止优化一处、弄坏另一处

**问题**：判定黄金集（91.7%）与 R1 泄漏集（P/R）完全隔离。
改抽取/归并可以悄悄把 91.7% 弄坏而没人发现。

**做法**
1. 新增 `eval/regression.ts`（`npm run regression`），一次跑三组：
   - 判定层：`run-eval` 口径（黄金集 v3 + 人工账本）
   - 端到端：`run-e2e` 口径（抽取账本，`E2E_PAD=id`）
   - R1：dev 的 P/R/cost（不跑 holdout）
2. 结果写入 `eval/baseline/regression.json`，与上一版比对，输出 `↑/↓/=`。
3. **回退红线（写死）**：
   - 判定层退 **≥2 条** → 必须回退
   - 端到端退 **≥2 条** → 必须回退
   - R1 的 `cost` 上升 → 回退或改开关默认值
4. 任何改动前先跑一次留档，改完再跑一次对比。

**验收**：一条命令出三组指标 + 与基线的 diff；红线被代码强制检查（不是靠我记得）。

**注意**：这一步会让「改一轮」从 1 分钟变成几分钟。**接受这个代价** —— 之前省下的时间都以"改了不知道好坏"的方式还回去了。

### A-4　半自动成因分桶 —— 把「人找假设」变成「工具报最大的洞」

**问题**：每轮的假设都是我读输出后手工想的。RSI 至少要走到「工具自己指出下一轮该改哪」。

**做法**
1. 对每条漏掉与每条误报，自动归入一个成因桶（判定规则写死，不用模型）：
   | 桶 | 判据 |
   |---|---|
   | `no_usage` | 该泄漏事实的命题存在，但没有任何使用点命中泄漏那句 |
   | `masked_by_presence` | 该 (角色, 命题) 的知情记录来自默认层，且场次不晚于使用 |
   | `delta_self` | 知情记录来自抽取的 delta，且 `about` 出现在该角色自己的台词里 |
   | `wrong_proposition` | 使用点命中的命题与标注的事实不是同一件事 |
   | `should_allow` | 误报的 (角色, 说法) 出现在 `must_not_flag` 里 |
2. 输出按桶计数降序：`本轮最大洞：no_usage（4 条）`。
3. 回合表的「下一轮目标」列直接抄这个输出。

**验收**：跑一次 `run-r1` 就能看到分桶排序，且能对上我手工分的那三条成因（① no_usage ② masked_by_presence ③ delta_self）。

## B. 补完之后继续的既有计划

按「数据指向什么就做什么」排，而不是按我兴趣排。桶的计数决定次序，但有几项与桶无关、必须并行推进。

### B-1　内核 · R1 层（由 A-4 的桶驱动）

| 项 | 状态 | 预估 |
|---|---|---|
| **cause ②：抽取区分「确立」与「提及」** | 未做 | `established_at` / `mentioned_at` 两个字段，R1 的 `mind` 只从确立起算 |
| **cause ③：delta 不把说话人自己的话记成知情** | 未做 | 指令加一条硬约束，成本极低 |
| `patient`（当事人/保管者知情） | 未做 | 抽取加 `patients`，规则同 `agents` |
| 作者显式声明（前史 / 特殊能力 / 职责范围） | **未设计** | 新增 `ledger_declare`，这三类**永远无法从剧本推断** |
| 职责性知情（律师、财务总监） | 未做 | 依赖上一条的职责声明 |
| 公开事实类型 | 未做 | 需要 `type` 字段，而抽取层按最小范围没抽 |

### B-2　内核 · 上游（这一层才是真正的瓶颈）

> 端到端 60.4% vs 判定层 91.7% 的差距，主体在**抽取→归并**：
> 同一事实被不同措辞抽成多条命题后没并上。

| 项 | 说明 |
|---|---|
| **改写级归并质量** | 「沈父将真正的遗嘱放在书房暗格里」与「书房暗格里有一份东西」被判 NEW |
| promotion 质量 | 在小剧本上退化成 10 个单元素组；应把命题所属场景与邻近原文喂进去 |
| 别名/说法覆盖 | 已做「最短指代片段」（R 33.3%→100%），但引用匹配仍不足 |

### B-3　产品表面（面试交付的硬要求，不能无限延后）

## C. 顺序与里程碑

```
A-1 holdout ─┐
A-2 标量目标 ─┼→ A-3 联合回归 → A-4 成因分桶 → 开始内核循环（B-1/B-2，按桶排序）
A-4 依赖 A-1/A-2 的字段
```

**里程碑**
| # | 交付 | 判据 |
|---|---|---|
| M1 | 测量站得住 | holdout 封存 + cost 定义 + 一条命令出三组指标 + 分桶排序 |
| M2 | R1 达到可用 | 误报率 < 40%（硬约束），cost 下降两轮以上 |
| M3 | 可演示 | 演示页上线 + `npx -y @ledger/mcp` 可用 + 录屏脚本跑通 |
| M4 | 可复现 | 任何人按 README 从零跑出与 `regression.json` 一致的数字 |

**贯穿红线**
1. 任何改动必过 A-3 的三组指标，任一红线触发就回退。
2. holdout 只在决定翻默认值时跑，跑一次记一次。
3. 代码不删，只关开关。
4. **B-3 不能无限延后**：如果 A 阶段超过两轮还没完，就先抽一轮做演示页——内核缺口是收敛问题，产品不可见是存在性问题。
