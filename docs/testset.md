# 测试集规范与演进记录

> 这份文档回答三个问题：**测试集测的是什么、它怎么变、以及每次变的时候指标跟着怎么变。**
>
> 起因是一次自我批评：项目的测试集一路「需要就加」——泄漏标注 3 → 10 → 14 条，
> 剧本 23 → 31 场，《茶馆》导入器改过两版 —— **但结果从没和测试集版本绑在一起记录**。
> 结果就是同一个指标在不同回合含义不同：e2e 出现过 60.4% / 47.9% / 54.2% / 58.3% 四个数字，
> 事后才发现差异来自配置或测试集不同，不是模型变了。

---

## 一、三条硬规则

### R1　测试集版本不可变
每个测试集有 `id@version#contenthash`，内容一变**必须**升版本（`npm run testset -- record`）。
注册表在 `evalsets/index.json`；`npm run testset -- verify` 检查「文件内容与登记的 hash 是否一致」。

> 借自 **lm-evaluation-harness** 的 `task version` 约定：数据集或打分逻辑一变就升版本，
> 这样「同一个 task 名下的两个分数」永远不会被混为一谈。

### R2　任何评测产出必须写明所用测试集
`runs/<id>/<task>.result.json` 与 `eval/baseline/regression.json` 都写入
`testset: "leaks@1#cc59a5ad9de1"` 这样的版本戳。**没有版本戳的分数不进入决策。**

### R3　测试集演进必须与结果同步记录
改测试集时，必须在本文「四、演进日志」加一行：**改了什么 / 为什么 / 改动前后所有指标**。
只改集不记指标，等于换尺子不记刻度。

## 二、三套测试集（各测一件事，互不替代）

| 集 | 版本 | 规模 | 测什么 | **不测什么** |
|---|---|---|---|---|
| **golden** | v3 | 48 样本 / 18 命题 | 判定层：mention → 命题绑定得对不对 | 不测抽取、不测 R1 |
| **leaks** | v4 | 14 条（10 dev + 4 holdout 封存） | R1：注入的泄漏能不能抓到、误报多少 | 分布是自造的，不代表真实剧本 |
| **chaguan** | v1 | 72 场 / 259 使用点 | R1 在**真实剧本**上的误报率（零标注） | 不能测召回（真实剧本无泄漏标注） |

### 为什么 chaguan 能零标注测精确率

专业剧本是**自洽**的。所以在其上跑 R1，报出的每一条几乎都是误报 ——
这正是我最初在自造剧本《旧账》正本上看到的现象（18 条全误报），
但现在分布是真实戏剧的分布。

> 它抓到过两个合成测试永远测不到的真 bug：`speakerOf` 把 `〔幕启：…`（带冒号的舞台指示）
> 当成说话人；命题说法被抽成人名（「小二德子」），谁提到该人名就命中。

### 为什么 leaks 仍然需要

chaguan 测不了召回。**召回必须靠注入**（等价于变异测试）：在剧本里埋入明确的知识泄漏，
并刻意安排「事实在更早、泄漏者不在场的场景里被确立」，否则在场者规则会把它自己掩盖掉。

### 污染控制

| 措施 | 说明 |
|---|---|
| **dev / holdout 分离** | leaks 的 14 条里 4 条封存；`run-r1` 默认只报 dev；`--holdout` 才解封 |
| **解封计数** | 每次解封必须在演进日志留痕 —— 反复看它就等于把它变成第二个 dev |
| **不许回填** | 人工发现的失败案例**不得**加进 dev（那等于用考题当练习题）；只能进新版本并重新标定 |
| **来源记录** | 每个测试集登记 `source`：自造 / 注入方式 / 公有领域依据 |
| **测试材料不外发** | `chaguan` 仅用于评测（公有领域但仍标注用途），演示一律用自造剧本 |

### 报告规范

不报单一数字。每次报指标必须带：**测试集版本 + 测量配置 + K 次中位数/极差**。
例：`e2e 28/48（26, 28, 28，K=3 中位数，golden@1，E2E_PAD=id）`。

> 借自 **Eval Factsheets**（arXiv 2512.04062）：评测要结构化记录配置、数据来源、
> 指标定义与已知限制，缺一项就无法复核。

## 三、标注规范（R1 注入式泄漏集）

1. **一条泄漏 = 某个角色用到了他不可能知道的信息。**
2. **事实必须确立在更早的、泄漏者不在场的场景里。**
   否则「首见场景在场者得知」这条默认规则会把泄漏者自己的台词当成本事的确立点，泄漏被自己掩盖
   —— 这是第 6 回合踩过的坑，v2 的 L-02 就是因为这个抓不到。
3. **排除「应当放过」的六类**，并单独登记到 `must_not_flag`：
   当事人 / 亲历 / 当场看到 / **误信被正确使用** / 本职 / 前史。
4. **类型二元**：`no_source`（无源信息）与 `timing`（超前知情）。
5. 每条必须写 `why`：**说明事实在哪一场被谁确立、泄漏者为什么不在场**。

## 五、已知限制

1. **chaguan 有材料噪声**：Wikisource 转录的人物表是连写无分隔的，导入器把 2 处残留行当成了台词。
   已列入待修（修完要升 `chaguan@2` 并记录指标变化）。
2. **chaguan 只测 R1 层**：`regression` 用**冻结缓存**跑它，所以捕捉不到上游（抽取/归并）改动；
   上游改动要重新抽取《茶馆》并替换缓存。
3. **holdout 只有 4 条**：一条值 25pp，只能粗判。要它真正起作用，需要扩到 ≥10 条。
4. **leaks 的分布自造**：即便 14 条也远小于真实剧本的复杂度，所以 `real` 指标不能省。
5. **静态测试集会被调参污染**：按 ACL 2026 GEM 的建议，长期应做动态/滚动刷新
   （定期换新剧本、换新注入点），否则跑得越久越不可信。

## 六、样本量下限与置信区间（**当前最大的测量缺陷**）

### 必须报 95% Wilson 区间，不允许只报点估计

比例型指标（准确率、精确率、召回率）在小样本、接近 0 或 1 时，正态近似会越界，
所以用 **Wilson score interval**（`src/rsi/metrics.ts` 的 `wilson()` / `formatRate()`）。
所有汇总输出已强制带上区间。

### 实测的区间宽度（这就是"测不出来"的量化证据）

| 指标 | 点估计 | 95% Wilson CI | 区间宽度 |
|---|---|---|---|
| 判定层 44/48 | 91.7% | [80.4%, 96.7%] | 16.3pp |
| R1 精确率 3/6（dev） | 50.0% | **[18.8%, 81.2%]** | **62.5pp** |
| R1 召回率 3/10（dev） | 30.0% | **[10.8%, 60.3%]** | **49.5pp** |
| real 报出率 9/259 | 3.5% | [1.8%, 6.5%] | **4.6pp** |

> **R1 的区间比 real 宽约 13 倍。** 区间重叠时，两次测量之间的差异**没有任何证据价值**。
>
> 这解释了本项目反复出现的现象：exp-007 的「P 50%→38.5%」、exp-008 的「P 50%→100%」，
> 全都在 62.5pp 宽的区间里 —— 那些比较**在统计上没有意义**。之前靠「精确率护栏 10pp」
> 做的裁决，依据的其实是噪声。

### 由此确定的规则

1. **R1 dev/holdout 只做定性判断**（"有没有抓到这个模式"），**不用于比较小幅差异**（<30pp 一律视为噪声）。
2. **`real` 指标是唯一有分辨率的连续指标**（区间宽 4.6pp），**以内核改进为主指标**。
   它的代价是测不了召回（真实剧本无泄漏标注）。
3. **要真正测 R1 的 P/R，标注量至少要 ~60–80 条**（当前 14 条差一个数量级）。
   按 Wilson 粗略估算：p≈0.5 时 ±10pp 需 n≈96；p≈0.3 时 ±10pp 需 n≈80。
4. **召回仍然只能靠注入测**，所以扩标注是绕不开的工作；在扩到量级之前，
   召回相关的结论一律标注「未测量」，不得引用点估计。

## 七、外部实践借鉴与三处更正（调研结论）

调研了四块：LLM-as-judge 评测方法论、无支撑断言/幻觉 benchmark、理论心智与事件共指评测、eval 框架工程约定。
下面是**已经采纳**的部分，以及它推翻了我此前哪些结论。

### 7.1 打分器也必须版本化（已落地）

`Inspect / inspect_evals` 的 `N-X` 双段版本规定：升 N 的触发条件包括
**打分逻辑、数据集、提示模板、影响结果的参数、影响结果的 bugfix** ——
也就是说，分数可比与否由**数据集 + 打分器**共同决定。

我此前只做了数据集版本（`leaks@1#hash`），**打分器一次没版本化**。
而 `src/audit/r1.ts` 被改过至少六次（`speakerOf`、人名过滤、短引用识别键、在场规则、显式优先、单元提升）——
每次都会改变「同一份账本会报出什么」。

现在结果里同时写两个戳：
```json
{ "testset": "leaks@1#cc59a5ad9de1", "scorer": "r1@93e022118bf3" }
```
且 **`npm run regression` 在打分器变化时拒绝生成差值**（只允许 `--save` 建立新基线）：
这是「测试集内容变了就拒绝跑」的对偶 —— **打分器变了就拒绝比**。

### 7.2 三处必须更正的结论

| 我写过的结论 | 调研后的判定 | 依据 |
|---|---|---|
| `rsi-log.md`：DeepSeek 95.8% 优于 JEV 91.7% | ❌ **不成立**，两者只差 2 条样本，McNemar 精确 **p = 0.50**；48 样本分辨力仅 ≈12pp | 配对检验；要 p<0.05 需 ≥6 个单向不一致 |
| `test-plan.md` P0-1：**存在**候选排序敏感性（reversed −4.2pp） | ❌ **不成立**，同样只是 2 条样本，p≈0.5，属噪声 | 同上 |
| 别名匹配用「一对一杯贪心」 | ⚠️ 方法不标准：贪心是 CEAF-e 的退化版（非最优指派） | 已换 **匈牙利最优指派**（`src/rsi/hungarian.ts`）；实测当前数据下结果相同（都 25/48），但风险消除 |

> **共同根因**：只有点估计、没有配对检验与区间。所以本轮同时加了
> `wilson()` 区间与 `eval/compare.ts`（McNemar 精确检验 + 区间对照 + 「不一致对<6 不下结论」）。

### 7.3 待采纳（已确认价值，尚未实现）

| 项 | 出处 | 落点 |
|---|---|---|
| **judge 与人类一致性**：请第二人双盲复标 ≥22/48 条，报 Cohen κ + Krippendorff α + 原始一致率；κ<0.6 则全项目数字只能叫「与 judge 的一致率」 | Zheng et al. 2306.05685 | 判定层 |
| **位置偏差测量**：同一对候选按 A/B 与 B/A 各判一次，报 position consistency | 2406.07791 | 判定层 |
| **decision-only judge 的校准指标**：JEV 有概率，应报 AUROC / ECE / Brier + risk-coverage（低置信弃权），并用 gold 概率做配对检验（功效远高于 48 条二值） | 2305.14975 | 判定层 |
| **知识状态做成 (命题 × 场 × 角色) 标签矩阵**，按来源（施事/在场/被告知/推理）分层报 micro-F1 与矩阵 exact match | ToMi / FANToM | R1 的 `mind(C)` |
| **最小对照题集**：同一剧本只改「某人是否在场」一位，只应让该格翻转（ToMi 的 `_tom/_no_tom` 手法） | ToMi 1808.09352 | R1 测试集设计 |
| **污染三件套**：canary GUID、13-gram 重叠、记忆探针；公版文学的补救是「**反事实改写**」（换人名地名保留结构）而非「防」 | BIG-bench / LiveCodeBench | `chaguan` 集 |
| **holdout 预算化**：解封从「计数」升级为「预算 + 理由 + 一次性」 | 调研建议 | 本文件 §二 |

## 八、叙事一致性 benchmark 的判决（最贴近本项目的一块）

调研找到两个 2026 年的直接同类工作，以及一组「无支撑断言」的成熟标注规范。结论比预期严厉：
**这个领域已经有基础设施，我的做法是它们的弱化版，而且我缺了它们最关键的一条纪律。**

### 8.1 STAGE（arXiv 2601.08510）—— 最接近我的任务，且有中文子集

- 151 部全长剧本（**109 英 + 42 中**），为每个角色在时间线每个点复原「state + epistemic access」
- epistemic access 四值：**目击 / 被告知 / 推断 / 不知道**
- 标注硬约束：**「同场次后续证据不得回流为前置知识」**（防 future leakage 进标注）
- 双盲一致率 91.7% 后裁定；judge 校准 Cohen κ = 0.82 / 0.86 / 0.76
- provenance 链路让专家核验从 5.4 min 降到 1.8 min，κ 从 0.62 升到 0.80
- 指标：影片级 macro + 1000 次 movie-cluster bootstrap CI；
  future-leakage / unknown-fact / unsupported-claim 作为**审计信号，不进正式排名**
- 中文部分：104 角色、690 states、Task III 1137 单轮 + 238 多轮

> **我第 6 回合自己总结的规矩「事实须在更早、泄漏者不在场的场景确立」，
> 就是它那条「不得回流」约束的弱化版。** 而且它有 42 部中文剧本 ——
> 这可以替代或补强我那个可能被污染的《茶馆》。

**我的差距**：`mind(C)` 只有三条启发式（施事 / 在场的首见场景 / 显式 delta），
而它是**每个角色在每个时间点的四值状态**，且区分「被告知」与「推断」。

### 8.2 ConStory-Bench（arXiv 2603.05890）与一个必须知道的事实

- 2000 prompts、5 类 19 子类矛盾分类法；机器 P .884 / R .550 / F1 .281
- **人类专家 recall 只有 4.5%–31.5%** → **漏报是这个任务的天然难点，不是我的实现缺陷**
- 原则：「earlier narrative content serves as the ground truth」

> 这条对我的意义：我一直在为「R1 召回只有 30%」自责。
> 但如果连人类专家在同类任务上也只有 4.5%–31.5%，那 30% 需要放在这个背景下解读，
> 而不是单纯当成「实现不行」。**当然这不构成免责，只构成基线参考。**

### 8.3 三值标签与分母规则（VeriScore / FActScore / RAGTruth）

| 做法 | 出处 | 对我的直接改法 |
|---|---|---|
| 三值标签：**support / contradict / inconclusive**，`inconclusive` **移出分母** | VeriScore (2406.19276)，κ=0.766 | 「不可核验」与「误信被正确引用」不该算进误报分母 |
| **无源（baseless）与冲突（conflict）分开报** | RAGTruth (2401.00396) | 我的 `no_source` 与 `timing` 两类应**分别报子集指标**，不能混成一个 P/R |
| **omission（该报未报）独立成一类**，不塞进 recall | FABLES (2404.01261) | 我的「漏掉」应单列，且能细分到成因桶 |
| **balanced accuracy** 治类别不平衡 | SummaC (2111.09525) | 我的 real 集 19 误报 vs 6 命中，必须报 balanced accuracy |
| 抽 20% 双标 + 第三人裁定，公开一致率/κ；**κ<0.7 先改规范而不是加标注量** | RAGTruth / VeriScore | 我的单标注者局面必须先解决 |
| F1@K 式截断上限 | SAFE/LongFact (2403.18802) | 防「少报求精确率便宜」的作弊方向 |

### 8.4 中文资源现状（重要：没有现成的）

- **不存在**「中文短剧剧本知识泄漏」的现成评测集或标注规范
- SkyScript-100M（2408.09333）有 6660 部中文短剧 / 约 8 万集，script↔shooting-script 配对，
  但**零一致性标注** —— 只能作为抽取层的压力测试材料，不能当评测集
- HalluQA / Chinese SimpleQA / ChineseFactEval 都是问答式，无叙事与时间线维度

**可行路径**：用 STAGE 的中文剧本 + 它的 epistemic-access 骨架做真实集，
配 ConStory-Bench 的 5×19 分类法自建标注规范。

核实了 STAGE 仓库（`github.com/roytian1992/STAGE_v0`，490MB / 2319 文件 / 2026-08 更新）。
**结论：schema 可以抄，数据不能拿。** 我此前「取它的 42 部中文剧本做真实集」的建议**不成立**。

### 9.1 三个硬事实

| 事实 | 原文/证据 | 后果 |
|---|---|---|
| **不发布剧本原文** | README：「Full screenplay text is not distributed in this repository. No `script.json` is included.」 | **不能用来测抽取** —— 而抽取正是我的瓶颈（54.2% vs 91.7%） |
| **剧本是受版权保护的在映影片** | `chinese_movie_info.csv` 里是《一代宗师》(2013)、《乘风破浪》(2017)、《三轮车夫》(1995)，附第三方 `script_url` | 可本地研究，**不能进仓库、不能随产品分发** |
| **仓库无 LICENSE 文件** | `license: null`；README 只有一节 Rights：「Screenplay rights remain with their respective holders」 | 标注本身的授权未声明 → **默认保留所有权利**，不能二次分发 |

### 9.2 但它的 schema 有一个我完全缺失的关键块：`context_protocol`

这是整个调研里最该抄的东西 —— 它把「上下文控制」写成**可审计的不变量**：

```jsonc
"context_protocol": {
  "full_screenplay_prefix_used": false,          // 不给模型整本前缀
  "previous_state_visible_to_memory_extractor": false,   // 上一步的模型输出不得回流
  "previous_state_model_projection": "claim_text_only",  // 只传递 claim 文本，不传递模型答案
  "memory_extractor_inputs": ["character", "aliases", "screenplay_interval"],
  "screenplay_scope": "previous_checkpoint_exclusive_to_current_checkpoint_inclusive"
}
```

> `screenplay_scope` 这一行，**就是我一直靠踩坑才总结出来的「不得未来泄漏」**。
> 它不是一个原则口号，而是写进数据文件、可被程序核验的边界。

我的评测结果里**没有任何这类声明** —— 也就是说，别人无法从我的产出判断
「抽取时到底看到了多少上下文」「上一场的结论有没有回流」。

### 9.3 输出 schema：claim 必须带证据场次

```jsonc
"output_schema": {
  "current_state": { "item_fields": ["claim", "evidence_scene_orders"], "type": "array" },
  "developments_since_previous_checkpoint": { "item_fields": ["claim", "evidence_scene_orders"] }
}
```

**每条 claim 都挂 `evidence_scene_orders`** —— 这就是「provenance-linked backbone」：
任何一条断言都能追到支撑它的场次。我的知识记录只有 `about` 片段与 `evidence: "(默认:在场)"`，
**没有场次级证据链**，所以无法机械核验「他到底凭哪一场得知的」。

### 9.4 指标分解：三值 × 两段

```
current_state_reference_coverage      development_reference_coverage
current_state_unsupported_rate        development_unsupported_rate
current_state_contradiction_rate      development_contradiction_rate
```

即 ①**覆盖率**（类召回）②**无支撑率** ③**矛盾率**，且**按「当前状态」与「自上次以来的发展」分段**。
这正好补上我「只报一个 P/R」的缺陷，也与 VeriScore 的三值标签一致。

### 9.5 另一处可全盘照搬的设计：`STAGE_Anon`

151 部片子同时提供 **ordinary 与 identity-anonymized 成对条件**。
这就是「反事实改写」的工程化版本：换掉身份保留结构，**能力测不变、记忆失效**。

**我该怎么做**：给《茶馆》写一个**反事实改写版**（换人名/地名/时代但不改结构与冲突），
原版与改写版配对使用 —— 这是**合法**（改写是我自己的作品）、**便宜**（一次改写）、
且能直接量化「记忆增益」的路径。这比去找 42 部受版权的中文剧本可行得多。

### 9.6 修订后的路线

| 原计划 | 修订 |
|---|---|
| 取 STAGE 的 42 部中文剧本做真实集 | ❌ 作废（无原文 + 受版权 + 无授权） |
| —— | ✅ 抄 `context_protocol`：把上下文不变量写进结果，可核验 |
| —— | ✅ 抄 claim 的 `evidence_scene_orders`：知识记录必须带场次证据链 |
| —— | ✅ 指标改三值（覆盖率 / 无支撑率 / 矛盾率）并按「当前状态 / 发展」分段 |
| —— | ✅ 给《茶馆》自制 **Anon 对照版**，配对使用以量化污染 |
