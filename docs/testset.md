# 测试集规范与演进记录

> 这份文档回答三个问题：**测试集测的是什么、它怎么变、以及每次变的时候指标跟着怎么变。**
>
> 起因是一次自我批评：项目的测试集一路「需要就加」——泄漏标注 3 → 10 → 14 条，
> 剧本 23 → 31 场，《茶馆》导入器改过两版 —— **但结果从没和测试集版本绑在一起记录**。
> 结果就是同一个指标在不同回合含义不同：e2e 出现过 60.4% / 47.9% / 54.2% / 58.3% 四个数字，
> 事后才发现差异来自配置或测试集不同，不是模型变了。

---

## 一、三条硬规则

### R1　测试集版本不可变
每个测试集有 `id@version#contenthash`，内容一变**必须**升版本（`npm run testset -- record`）。
注册表在 `evalsets/index.json`；`npm run testset -- verify` 检查「文件内容与登记的 hash 是否一致」。

> 借自 **lm-evaluation-harness** 的 `task version` 约定：数据集或打分逻辑一变就升版本，
> 这样「同一个 task 名下的两个分数」永远不会被混为一谈。

### R2　任何评测产出必须写明所用测试集
`runs/<id>/<task>.result.json` 与 `eval/baseline/regression.json` 都写入
`testset: "leaks@1#cc59a5ad9de1"` 这样的版本戳。**没有版本戳的分数不进入决策。**

### R3　测试集演进必须与结果同步记录
改测试集时，必须在本文「四、演进日志」加一行：**改了什么 / 为什么 / 改动前后所有指标**。
只改集不记指标，等于换尺子不记刻度。

## 二、三套测试集（各测一件事，互不替代）

| 集 | 版本 | 规模 | 测什么 | **不测什么** |
|---|---|---|---|---|
| **golden** | v3 | 48 样本 / 18 命题 | 判定层：mention → 命题绑定得对不对 | 不测抽取、不测 R1 |
| **leaks** | v4 | 14 条（10 dev + 4 holdout 封存） | R1：注入的泄漏能不能抓到、误报多少 | 分布是自造的，不代表真实剧本 |
| **chaguan** | v1 | 72 场 / 259 使用点 | R1 在**真实剧本**上的误报率（零标注） | 不能测召回（真实剧本无泄漏标注） |

### 为什么 chaguan 能零标注测精确率

专业剧本是**自洽**的。所以在其上跑 R1，报出的每一条几乎都是误报 ——
这正是我最初在自造剧本《旧账》正本上看到的现象（18 条全误报），
但现在分布是真实戏剧的分布。

> 它抓到过两个合成测试永远测不到的真 bug：`speakerOf` 把 `〔幕启：…`（带冒号的舞台指示）
> 当成说话人；命题说法被抽成人名（「小二德子」），谁提到该人名就命中。

### 为什么 leaks 仍然需要

chaguan 测不了召回。**召回必须靠注入**（等价于变异测试）：在剧本里埋入明确的知识泄漏，
并刻意安排「事实在更早、泄漏者不在场的场景里被确立」，否则在场者规则会把它自己掩盖掉。

### 污染控制

| 措施 | 说明 |
|---|---|
| **dev / holdout 分离** | leaks 的 14 条里 4 条封存；`run-r1` 默认只报 dev；`--holdout` 才解封 |
| **解封计数** | 每次解封必须在演进日志留痕 —— 反复看它就等于把它变成第二个 dev |
| **不许回填** | 人工发现的失败案例**不得**加进 dev（那等于用考题当练习题）；只能进新版本并重新标定 |
| **来源记录** | 每个测试集登记 `source`：自造 / 注入方式 / 公有领域依据 |
| **测试材料不外发** | `chaguan` 仅用于评测（公有领域但仍标注用途），演示一律用自造剧本 |

### 报告规范

不报单一数字。每次报指标必须带：**测试集版本 + 测量配置 + K 次中位数/极差**。
例：`e2e 28/48（26, 28, 28，K=3 中位数，golden@1，E2E_PAD=id）`。

> 借自 **Eval Factsheets**（arXiv 2512.04062）：评测要结构化记录配置、数据来源、
> 指标定义与已知限制，缺一项就无法复核。

## 三、标注规范（R1 注入式泄漏集）

1. **一条泄漏 = 某个角色用到了他不可能知道的信息。**
2. **事实必须确立在更早的、泄漏者不在场的场景里。**
   否则「首见场景在场者得知」这条默认规则会把泄漏者自己的台词当成本事的确立点，泄漏被自己掩盖
   —— 这是第 6 回合踩过的坑，v2 的 L-02 就是因为这个抓不到。
3. **排除「应当放过」的六类**，并单独登记到 `must_not_flag`：
   当事人 / 亲历 / 当场看到 / **误信被正确使用** / 本职 / 前史。
4. **类型二元**：`no_source`（无源信息）与 `timing`（超前知情）。
5. 每条必须写 `why`：**说明事实在哪一场被谁确立、泄漏者为什么不在场**。

## 五、已知限制

1. **chaguan 有材料噪声**：Wikisource 转录的人物表是连写无分隔的，导入器把 2 处残留行当成了台词。
   已列入待修（修完要升 `chaguan@2` 并记录指标变化）。
2. **chaguan 只测 R1 层**：`regression` 用**冻结缓存**跑它，所以捕捉不到上游（抽取/归并）改动；
   上游改动要重新抽取《茶馆》并替换缓存。
3. **holdout 只有 4 条**：一条值 25pp，只能粗判。要它真正起作用，需要扩到 ≥10 条。
4. **leaks 的分布自造**：即便 14 条也远小于真实剧本的复杂度，所以 `real` 指标不能省。
5. **静态测试集会被调参污染**：按 ACL 2026 GEM 的建议，长期应做动态/滚动刷新
   （定期换新剧本、换新注入点），否则跑得越久越不可信。

## 六、样本量下限与置信区间（**当前最大的测量缺陷**）

### 必须报 95% Wilson 区间，不允许只报点估计

比例型指标（准确率、精确率、召回率）在小样本、接近 0 或 1 时，正态近似会越界，
所以用 **Wilson score interval**（`src/rsi/metrics.ts` 的 `wilson()` / `formatRate()`）。
所有汇总输出已强制带上区间。

### 实测的区间宽度（这就是"测不出来"的量化证据）

| 指标 | 点估计 | 95% Wilson CI | 区间宽度 |
|---|---|---|---|
| 判定层 44/48 | 91.7% | [80.4%, 96.7%] | 16.3pp |
| R1 精确率 3/6（dev） | 50.0% | **[18.8%, 81.2%]** | **62.5pp** |
| R1 召回率 3/10（dev） | 30.0% | **[10.8%, 60.3%]** | **49.5pp** |
| real 报出率 9/259 | 3.5% | [1.8%, 6.5%] | **4.6pp** |

> **R1 的区间比 real 宽约 13 倍。** 区间重叠时，两次测量之间的差异**没有任何证据价值**。
>
> 这解释了本项目反复出现的现象：exp-007 的「P 50%→38.5%」、exp-008 的「P 50%→100%」，
> 全都在 62.5pp 宽的区间里 —— 那些比较**在统计上没有意义**。之前靠「精确率护栏 10pp」
> 做的裁决，依据的其实是噪声。

### 由此确定的规则

1. **R1 dev/holdout 只做定性判断**（"有没有抓到这个模式"），**不用于比较小幅差异**（<30pp 一律视为噪声）。
2. **`real` 指标是唯一有分辨率的连续指标**（区间宽 4.6pp），**以内核改进为主指标**。
   它的代价是测不了召回（真实剧本无泄漏标注）。
3. **要真正测 R1 的 P/R，标注量至少要 ~60–80 条**（当前 14 条差一个数量级）。
   按 Wilson 粗略估算：p≈0.5 时 ±10pp 需 n≈96；p≈0.3 时 ±10pp 需 n≈80。
4. **召回仍然只能靠注入测**，所以扩标注是绕不开的工作；在扩到量级之前，
   召回相关的结论一律标注「未测量」，不得引用点估计。

## 七、外部实践借鉴与三处更正（调研结论）

调研了四块：LLM-as-judge 评测方法论、无支撑断言/幻觉 benchmark、理论心智与事件共指评测、eval 框架工程约定。
下面是**已经采纳**的部分，以及它推翻了我此前哪些结论。

### 7.1 打分器也必须版本化（已落地）

`Inspect / inspect_evals` 的 `N-X` 双段版本规定：升 N 的触发条件包括
**打分逻辑、数据集、提示模板、影响结果的参数、影响结果的 bugfix** ——
也就是说，分数可比与否由**数据集 + 打分器**共同决定。

我此前只做了数据集版本（`leaks@1#hash`），**打分器一次没版本化**。
而 `src/audit/r1.ts` 被改过至少六次（`speakerOf`、人名过滤、短引用识别键、在场规则、显式优先、单元提升）——
每次都会改变「同一份账本会报出什么」。

现在结果里同时写两个戳：
```json
{ "testset": "leaks@1#cc59a5ad9de1", "scorer": "r1@93e022118bf3" }
```
且 **`npm run regression` 在打分器变化时拒绝生成差值**（只允许 `--save` 建立新基线）：
这是「测试集内容变了就拒绝跑」的对偶 —— **打分器变了就拒绝比**。

### 7.2 三处必须更正的结论

| 我写过的结论 | 调研后的判定 | 依据 |
|---|---|---|
| `rsi-log.md`：DeepSeek 95.8% 优于 JEV 91.7% | ❌ **不成立**，两者只差 2 条样本，McNemar 精确 **p = 0.50**；48 样本分辨力仅 ≈12pp | 配对检验；要 p<0.05 需 ≥6 个单向不一致 |
| `test-plan.md` P0-1：**存在**候选排序敏感性（reversed −4.2pp） | ❌ **不成立**，同样只是 2 条样本，p≈0.5，属噪声 | 同上 |
| 别名匹配用「一对一杯贪心」 | ⚠️ 方法不标准：贪心是 CEAF-e 的退化版（非最优指派） | 已换 **匈牙利最优指派**（`src/rsi/hungarian.ts`）；实测当前数据下结果相同（都 25/48），但风险消除 |

> **共同根因**：只有点估计、没有配对检验与区间。所以本轮同时加了
> `wilson()` 区间与 `eval/compare.ts`（McNemar 精确检验 + 区间对照 + 「不一致对<6 不下结论」）。

### 7.3 待采纳（已确认价值，尚未实现）

| 项 | 出处 | 落点 |
|---|---|---|
| **judge 与人类一致性**：请第二人双盲复标 ≥22/48 条，报 Cohen κ + Krippendorff α + 原始一致率；κ<0.6 则全项目数字只能叫「与 judge 的一致率」 | Zheng et al. 2306.05685 | 判定层 |
| **位置偏差测量**：同一对候选按 A/B 与 B/A 各判一次，报 position consistency | 2406.07791 | 判定层 |
| **decision-only judge 的校准指标**：JEV 有概率，应报 AUROC / ECE / Brier + risk-coverage（低置信弃权），并用 gold 概率做配对检验（功效远高于 48 条二值） | 2305.14975 | 判定层 |
| **知识状态做成 (命题 × 场 × 角色) 标签矩阵**，按来源（施事/在场/被告知/推理）分层报 micro-F1 与矩阵 exact match | ToMi / FANToM | R1 的 `mind(C)` |
| **最小对照题集**：同一剧本只改「某人是否在场」一位，只应让该格翻转（ToMi 的 `_tom/_no_tom` 手法） | ToMi 1808.09352 | R1 测试集设计 |
| **污染三件套**：canary GUID、13-gram 重叠、记忆探针；公版文学的补救是「**反事实改写**」（换人名地名保留结构）而非「防」 | BIG-bench / LiveCodeBench | `chaguan` 集 |
| **holdout 预算化**：解封从「计数」升级为「预算 + 理由 + 一次性」 | 调研建议 | 本文件 §二 |
