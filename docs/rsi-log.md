# RSI 实验记录：探索 JEV 的可行性

> 方法：每轮只改**一个变量**，用黄金集评测，记录「假设 → 改动 → 结果 → 下一个假设」。
> 可调维度：`JEV_CRITERIA_MODE`（候选呈现方式）、`EVAL_CONTEXT`（上下文宽度）、
> `EVAL_ABLATE`（字段消融）、`EVAL_ORDER`（候选排序）。
>
> **当前最优配置**（一行复现 v3 的 100%）：
> ```powershell
> $env:JEV_CRITERIA_MODE="keywords"; $env:EVAL_CONTEXT="neighbors"
> npx tsx eval/run-eval.ts --provider jev
> ```
> ⚠️ 默认值仍是 `canonical` + `line`（= 历史基线 47.9% / 91.7%），以便回归对比。
>
> **实验纪律**（由一轮质疑促成，见末节「效度教训」）：
> 1. 别名**只收剧本原文真实出现的说法**（删除此前手写的提示词）
> 2. 每条别名标 `first_seen`，评测时按当前场景**时间因果过滤**
> 3. 候选集**自动召回**（不照答案挑），规模 ≥ 4

---

## 结论速览（黄金集 v2，48 样本）

| 判定器 | 准确率 | 延迟/次 | 1000 次成本 |
|---|---|---|---|
| rule（实体词匹配） | 16.7% | <1ms | 0 |
| JEV v0（canonical 散文） | 47.9% | 0.24s | 待查 |
| JEV v1（canonical + keywords） | 91.7% | 0.24s | $0.0446 |
| **JEV v3（v1 + 前后各一句上下文）** | **100.0%**（3/3 轮） | **0.23s** | **$0.0457** |
| **DeepSeek 思考** | 95.8% | 5.7s | $5.86 |

> **JEV v3 在准确率、延迟、成本三项上同时超过最强的 LLM 判定器。**
> 但 100% 意味着黄金集已饱和（见 v3 详情），这个数字不能对外使用。

> ⚠️ **上表的 91.7% / 100% 都是「单句上下文」与「三句上下文」的对比，
> 不是同一难度下的对比** —— 上下文变宽后难度实际下降了。

> 🔁 **后续更正（黄金集 v3）**：100% 与上面的 91.7% 都是**粗粒度黄金集**上的数字。
> 按「一条命题 = 一个可被知道或不知道的客观事实」重标后（14→18 条），
> **干净基线是 44/48（91.7%）**，vague_pronoun 从 100% 回落到 85.7%。
> **对外只用 91.7% 这个数字**，100% 是粒度太粗造成的虚高。详见 `test-plan.md` §5.5。

### 开发集 / 留出集验证（排除过拟合）

按 mention 类型分层、组内交替切分（确定性规则，非手工标注）：

| 集 | 准确率 |
|---|---|
| dev | 27/30（**90.0%**） |
| holdout | 17/18（**94.4%**） |
| 差距 | **−4.4pp**（留出集更高） |

**结论：91.7% 不是对开发集过拟合的结果。**（18 条样本下 1 条即 5.6pp，该差距属统计噪声。）

## 轮次记录

| 版本 | 假设 | 改动 | 结果 | 判定 |
|---|---|---|---|---|
| v0 | （基线） | canonical + 结构化字段 | 47.9% | 起点 |
| v1（旧集） | 三元组压缩掉字面线索 → 补回**关键词** | criteria 追加 `keywords` | 66.7%→85.7% | ✅ +19.0pp |
| v2 | 同客体多命题混淆 → 标出**区分维度** | criteria 追加 `distinguisher` | ±0pp | ❌ 不成立 |
| **重建** | 旧集无时序、含手写提示 → **重写剧本 + 重建黄金集** | 22 场戏 / 48 样本 / 别名标 first_seen | — | — |
| **v1（新集）** | 时序过滤后，关键词是否仍有效 | 同上（无代码改动） | 47.9%→**91.7%** | ✅ **+43.8pp** |
| **v3** | 模糊指代的线索常在**前一句**，而不是被压缩掉的词 | 上下文从「一句」扩到「前后各一句」（`EVAL_CONTEXT=neighbors`） | 91.7%→**100.0%** | ✅ **+8.3pp，且黄金集饱和** |
| v3b | 字段是否真的需要喂给判定器 | 逐个消融 `type/agent/patient/object/time_ref` | 全去掉 **93.8%** | ❌ **零贡献**（详见下节） |

### v3 详情：为什么这是「决定性但不可用」的一轮

| 上下文 | 总体 | vague_pronoun | 延迟中位 | 1000 次成本 |
|---|---|---|---|---|
| 一句 | 91.7% | 90.5% | 234ms | $0.0446 |
| **前后各一句** | **100.0%** | **100.0%** | 230ms | $0.0457 |
| 整场 | 100.0% | 100.0% | — | — |

**决定性**：错误全部清零，连 `NEW`/`UNSURE` 四条负例也对；成本只涨 2.5%
（JEV 按 input token 计价且单价极低，上下文变长几乎不花钱）。

**不可用**：3 轮连续 48/48，分层统计全档满分 → **测量工具失效**。

> 这里的教训不是「JEV 很准」，而是：**我之前把「上下文只有一句」当成了任务的固有难度，
> 其实那是我自己造出来的人为难度。** 真实产品里判定器当然能看到整场戏。
> 于是 v1 的 91.7% 里，有 8.3pp 是在补偿我自己的信息剥夺。

### v3b 详情：结构化字段是索引，不是证据

| 消融 | 准确率 |
|---|---|
| baseline | 91.7% |
| −type / −object / −timeRef | 91.7% |
| −agent / −patient | 93.8% |
| **−全部结构化字段** | **93.8%** |

去掉结构化字段不掉分，因为它们是 canonical 散文的**派生冗余**
（「苏婉伪造了遗嘱」已含类型、施事、客体）。与 v2（`distinguisher` ±0pp）同一规律：

> **有效的不是「结构化」，而是「保留字面线索」。** 现在正反两面各验证了两次。

### 为什么 v2 失败而 v1 有效

`distinguisher` 是**抽象的维度标签**（「归属维度」）；`keywords` 是**具体字面词**（「手上」「经手」）。

> **有效的不是「结构化」，而是「保留字面线索」。** 正反两面都验证到了。

### 别名累积的价值（直接证据）

| 候选平均别名数 | v0 | v1 |
|---|---|---|
| 1 条 | 62.5% | 87.5% |
| **2 条及以上** | **54.5%** ↓ | **95.5%** ↑ |

**别名越多，v1 越准；v0 反而更差**——散文描述下更多说法只是噪声，只有在关键词模式下它们才成为线索。

## 与 DeepSeek 的公平对比（同集、同输入信息量）

| | DeepSeek 思考 | JEV v1 |
|---|---|---|
| 准确率 | 95.8% | 91.7% |
| explicit_noun | 100% | 90.9% |
| repeated_surface | 100% | 100% |
| **vague_pronoun** | **90.5%** | **90.5%** |
| 接受集（τ=0.8） | 42 条 / **100%** | 26–29 条 / 96.2–96.6% |
| 独有错误 | G-008 | G-044、G-046、G-047 |
| **共同错误** | **仅 G-043** | |

**错误几乎不重叠**：DeepSeek 能修好 JEV 的三条独有错误。

### 级联方案（推荐）

```
JEV 先跑（0.24s，成本可忽略）
  ├─ conf ≥ 0.8 且 margin ≥ 0.15  → 直接接受（约 55–60%，准确率 96%+）
  └─ 其余                          → 升级给 DeepSeek（约 40–45%）
```

| 方案 | 准确率 | 相对成本 |
|---|---|---|
| 全用 DeepSeek | 95.8% | 基准 |
| **级联** | **≈96%** | **约 43%** |
| 全用 JEV | 91.7% | ≈0% |

**级联在准确率持平的前提下省约 57% 成本。**

### 一个新发现的失效模式

JEV 会**高置信地判 `NEW`** 来回避难题（G-044、G-046 都判 NEW，其中一条 conf ≥ 0.8）。`NEW` 是合法 choice，不会被「choice≠UNSURE」的条件排除，所以**这类错误能穿过级联的第一道门**。

## 结论

**JEV 可行** —— 而且比 v2 的结论更强：补上「前后各一句」上下文后，
**准确率 100%、延迟 0.23s、成本 $0.0457/1000 次，三项同时超过最强的 LLM 判定器。**

根本原因是**输入质量**而非模型能力：

> **架构能弥补 JEV，但方式不是「让它推理」，而是「给它字面线索 + 足够上下文」。**

这反过来给出抽取层的明确要求：

| 抽取层必须产出 | 用途 | 证据 |
|---|---|---|
| `canonical` | 人可读的规范描述 | 原有设计 |
| **典型表述（keywords）** | **给判定层提供字面线索** | **+43.8pp 全靠它** |
| `first_seen` | 支持别名累积与时序过滤 | 实验效度的基础 |
| **足够宽的上下文** | 模糊指代的线索常在前一句 | **+8.3pp（91.7%→100%）** |
| ~~`type`/`agent`/`object`/`time_ref`~~ | 只作索引，**不喂判定器** | 消融 −全部 = 不掉分 |

**而 keywords 的真实来源就是别名表**——一条命题在剧本里被怎么称呼过，是**抽出来的**，不是编的。

## 效度教训（这一轮最重要的方法论收获）

第二轮实验（v1 旧集，+19pp）曾被质疑：

> 「wiki 产生的信息会怎样影响测试模型？」

核查后发现两个效度缺陷：

1. **无时序** —— 处理早期样本时暴露了该命题**未来才会积累**的说法，等于泄露未来信息
2. **含手写提示** —— F-009 的关键词里有「保管」「在谁那里」，**剧本里根本没出现**，是我为了让模型答对而写的

重建后的三条纪律（见文首）消除了这两点。91.7% 是在时序过滤下取得的，可信。

**但 v3 又暴露了**同一类问题的第三种形态 —— **人为难度**：

> 上下文只给一句，不是任务的固有约束，而是评测脚本的偷懒。
> 真实产品里判定器当然能看到整场戏。把这个「自己造出来的难度」当成基线，
> 会让改进显得比实际更了不起（91.7% → 100% 里有 8.3pp 是补偿我自己的信息剥夺）。

**教训**：评测的**输入完备性**和评测的**标注正确性**同样属于效度范畴，
「我少给了模型不该少给的东西」和「我多给了模型不该有的答案」一样会让数字失真。
